# 詰まった工程を「手作業」で押し切る — ドット絵発注書

2026-10-27 · sakuri の指示「ボトルネック箇所は、ゴリ押し（クリック）でも解消できるようにしよう。工業的に手動から自動化の流れとして正しい。そのための対応グラフィックも必要。」

帯の工程の山（QA トレイのカード山・ビルド台のカード山・出荷スタックの箱）のうち、詰まっている（ボトルネックの）山をクリックすると、みゅけが手作業でその工程を進める。クリックしている間、山の上に「みゅけの前足が作業している」絵を出して、手作業で押し切っていることが一目で分かるようにする。設備や人を買えば手作業は要らなくなる（手動 → 自動化）。

コードで絵を描くのは禁止なので、以下をドット絵で発注する。

## 発注リスト

すべて原寸のまま帯に等倍で置く。下端中央アンカー（山の上に乗る）。色は `graphics/sprites.js` の既存パレットだけを使う（新色ゼロが目標）。前足はみゅけ（三毛猫: クリーム地にオレンジと焦げ茶のぶち）の前足に見えること。肉球はピンク。

| 名前 | サイズ | 内容 |
|---|---|---|
| `fx_handwork_test_0` / `_1` | 18×16 | テスト工程の手作業。前足が赤ペン（またはチェックのはんこ）を持ち、下のカードに印をつける。0 は持ち上げ、1 は押し当て（小さな衝撃の線2本） |
| `fx_handwork_build_0` / `_1` | 18×16 | ビルド工程の手作業。前足が小さな木づち（またはスパナ）でカードの束をとんとん叩く。0 は振り上げ、1 は振り下ろし（衝撃の線） |
| `fx_handwork_ship_0` / `_1` | 18×16 | 出荷工程の手作業。前足が段ボール箱（`icon_box` と同じ配色を小さく）を横に押す。0 は構え、1 は押し込み（後ろに小さな土ぼこり） |
| `icon_tap_0` / `_1` | 10×10 | 「ここを押せる」の合図。下向きに指す小さな前足（肉球が見える）。0 と 1 で 1px 上下して点滅に使う |

## 使い方（参考）

- 詰まった山にカーソルを合わせると `icon_tap_*` が山の上で上下する。
- クリックするたびに、その工程の `fx_handwork_<工程>_0` → `_1` を約 0.25 秒ずつ出す。連打中は続けて動く。
- `_0` と `_1` は同じキャンバス・同じ足元で、入れ替えても位置が跳ねないこと。

## 納品物

1. `graphics/env-sprites-handwork.js` — `window.MIYUKE_ENV_SPRITES_HANDWORK = { palette, sprites: { 名前: string[] } }`。`graphics/env-sprites-bugs.js` と同じ形式（`.` = 透明、各行は指定幅ちょうど、行数は指定どおり）。絵ごとにサイズ・アンカー・用途の1行コメント。
2. `graphics/env-preview-handwork/<名前>.png`（4倍・最近傍・#808080 の地）と `contact-sheet.png`・`anim.png`（2コマを並べたもの）。描画スクリプトは `graphics/render-env-preview-bugs.cjs` に倣い標準ライブラリのみ。
3. `research/HANDWORK_ART_MANIFEST.md` — 絵ごとに名前・サイズ・内容・使ったパレット文字・新色（あれば hex と理由）。
