## 1. 視覚テーゼ — 何が「プログラマのオフィス」を3秒で読ませるか

### 1.1 テーゼ（3行）

1. **コードが光っている場所が開発現場である。** モニタの中身が「緑の棒」ではなく多色のシンタックスハイライトとして読めた瞬間、その机は事務机ではなくプログラマの机になる。
2. **仕事の状態が見える化されている場所が開発チームである。** カンバン／スプリントボードに付箋が流れ、サーバの LED が瞬き、CI の緑チェックが並ぶ——「進捗が壁と機械に貼り出されている」のが開発オフィスの景色。
3. **猫の温かさは残し、素材だけを差し替える。** 木と紙の「工作の部屋」から、ラミネート・金属・ホワイトボード・段ボールの「小さなソフトウェア会社のオフィス」へ。段ボール・コーヒー・付箋のパステルが、温かい猫と冷たい機材の橋になる。

### 1.2 サイニファイア（signifier）ランキング

「3秒でプログラマのオフィスと分かる」強さ順。根拠は参照タイトル・実オフィスの反復出現。

| 順位 | 要素 | なぜ効くか | 本作での現状 |
|---|---|---|---|
| 1 | **コードが表示されたモニタ**（多色シンタックス、行番号、カーソル） | モニタ自体は事務職にもあるが、「色分けされたコード行」は開発者専用。Game Dev Tycoon のオフィスが読める最大要因も机上のコンピュータ群＋画面 | △ 単モニタに緑スタブ3行のみ。色が1色＝「何かの機械」止まり |
| 2 | **カンバン／スプリントのホワイトボード＋付箋** | アジャイルの儀式そのもの。付箋の列移動＝進捗の可視化は Software Inc 系の「開発サイクル管理」の景色でもある | ✗ 木の標識ボード（工作・案内板の記号） |
| 3 | **サーバラックの LED** | 点滅する小さい光の列は「インフラがある会社」の最短記号。Software Inc でもサーバ設置は独立要素 | ✗ スプライト `prop_server` が未使用で眠っている |
| 4 | **デュアルモニタ構成** | 「モニタ2枚」は開発者の作業環境のステレオタイプとして最強級。1枚との差は遠目でも分かる | ✗ 全机が単モニタ |
| 5 | **オフィスチェア**（メッシュ背もたれ＋ヘッドレスト＋キャスター） | 椅子の形は「オフィス」の汎用記号。逆に椅子なしで座る猫は「床に座る」和風/牧場寄りに読める | ✗ 椅子が存在しない（机に座位ポーズのみ） |
| 6 | **付箋の散らかり**（モニタ縁・ボード端・机端） | 小さいのに効果絶大。ピクセルオフィス系アセット（Isometric Interiors のオフィス拡張等）でも sticky notes は名物小物として独立カテゴリ | ✗ なし |
| 7 | **技術書の本棚**（色背表紙の列、数冊は斜め） | 背表紙の色帯の列は「技術書棚」の記号（O'Reilly の動物表紙ネタまで含む） | △ 研究机に本の山3冊のみ |
| 8 | **コーヒーギア**（マグ＜ドリッパー/マシン） | 開発者とコーヒーは不可分。Game Company Simulator ではコーヒーマシン近傍に速度バフが付くほど定番 | △ 赤マグのみ（ただしマグ自体は温かさの橋として残す価値あり） |
| 9 | **段ボール箱**（出荷・引っ越し・保管） | スタートアップと物流の記号。本作では「完成作＝箱」が既にコアメタファー | ○ 作品棚に既にある（強い資産。そのまま活きる） |
| 10 | **デスクランプ／ヘッドホン／ケーブル・電源タップ** | 解像度が上がる小物群。夜のオフィスの光、集中の記号、機材の裏側 | ✗ なし |

補足: 既にゲーム内にいる**ラバーダック検査員**は「ラバーダック・デバッグ」という開発者文化そのもので、現行アセットで最もテーマに合っている存在。アヒルはそのまま主役級サイニファイアとして扱う。

### 1.3 やめるもの（現行の「工作・牧場」記号）

- **木の過剰使用**: 机・棚・ボード枠・イーゼル・台座・柵まで全部木＝「木工所/山小屋」。木は段ボールと一部の天板に限定し、主素材をラミネート（淡グレー）＋金属（スレート）に移す。
- **柵（フェンス）**: 棚の背後の柵は Tiny Pasture 由来の牧場記号で、本作で最もテーマから外れた物体。撤去する（R9 的にも「大きな背面物」の削減になり正本適合が上がる）。
- **紙面クリームを全表面の既定色にする**こと（メニュー）。紙は「付箋・印刷物・猫の毛色」のための色に格下げし、UI の地はエディタ側に寄せる（§3）。
- **イーゼル/ポスター看板**: クラフトフェアの記号。保管段ボール＋貼り紙に置換する（§2.7）。
- **暖色ラグの矩形**: 各クラスタの足元の暖色は「和室・工房」感の静かな主因。カーペットタイル（寒色グレー）かアンチファティーグマット（濃グレー）に変えるだけで景色の温度が変わる。
- 逆に**残す温かさ**: 猫そのもの、段ボールの茶、コーヒーマグの赤、報酬の金、付箋のパステル。これらが §3 のシンタックスパステルと同色系で、帯とメニューの橋になる。

## 2. 帯プラン — 家具ごとの変換

座標・ゾーンは現行踏襲（棚 0.12W／主机 0.30W／研究 0.47W／（空き）0.55W／第2机 0.63W／トロフィー 0.75W／ボードは主机上空 y4–34）。描画順 R3 は不変。実装種別: = 既存描画の色・形の差し替えのみ／= 手続き描画の追加・変更／= 新規スプライト or 生成画が要るもの。

### 2.1 プロジェクトボード → カンバンホワイトボード（最優先・テーマの顔）

- 物体: 木枠標識 → **アルミ枠ホワイトボード**（脚は細い金属ポール2本、現行支柱の位置そのまま）。面は白〜淡グレー（`#E9EFFF` s 系）。ホワイトボードは実物が「明るい面」なので、帯上部に明るい矩形が立つこと自体がオフィスの景色になる。
- 中身の文法（算数は現行 `projectBoardModel()` を完全流用し、見せ方だけ差し替える）:
- 3カラム見出し: **TODO / DOING / DONE**（小さなマーカー文字色: グレー／青／緑）。
- feat（節目）が**付箋**になる: 未着手の feat は TODO 列に淡色付箋、現在の feat は DOING 列に濃色付箋、完了 feat は DONE 列に移り緑チェック。進捗 = 付箋が列を進むこと自体。付箋色はシンタックスパステル（黄 `#FFDA64`・桃 `#F49CAC`・淡青 `#71BED3`・緑 `#85CA91`）を feat ごとに循環。
- 太バーと巨大 % は**維持**する（sakuri の「一目で読める」要求が付箋の可愛さより優先）。配置は現行どおり下段バー＋左上 %。ただしバーの充填色は「マーカーの緑」に寄せ、枠は木→アルミグレー。
- 企画中（planning）は BACKLOG 列に 💡 付箋が積まれる絵にする（現行の金バー点滅を「アイデア付箋の増加」に翻訳）。
- 詰まり（bottleneck）は**赤い付箋＋⚠** を DOING 列に貼る（現行の赤プレートの翻訳。信号の一本化は維持し、HUD チップは工程名の文面担当のまま）。
- リリース瞬間の金枠パルスは「DONE 列の付箋が一斉に光る」に翻訳可（現行パルスの対象を枠→DONE付箋に移す）。難しければ金枠維持でも可。
- 片隅に小さな**貼り紙/写真**（旧ポスター prop_wall_1 の受け皿。§2.7 と連動）。
- 第2ライン版（小型 108 幅）も同じ文法で白板化する。カラムは TODO/DONE の2列に簡略化してよい。
- 正本チェック: 占有領域は現行ボードと同一（y4–34、支柱ありの自立家具）で、R9 の「背面パネル」化ではない（現行ボード自体が認可済み例外、その素材変更）。歩行者・吹き出しは現行どおり手前（R2/R3）。

### 2.2 主机クラスタ（0.30W）→ 開発デスク

- 机天板: 木板 `#b08954` → **ラミネート天板**（淡グレー `#C1C8CB` L 系＋前面の濃色エッジバンド `#465464`）。脚は木→ダークメタル。机の「面の色」が変わるだけでクラスタ全体の温度が下がる。
- モニタ（prop_pc / 手続き描画）の中身を「コード」に作り替える:
- 現行の緑スタブ3行 → **シンタックス行**: 行ごとに色セグメント（青=キーワード `#578BC5`、桃=文字列 `#F49CAC`、黄=関数 `#FFDA64`、緑=コメント/型 `#85CA91`、淡白=通常コード）＋左端に行番号ガター（濃グレーに小さな数字ドット列）。行の長さ・インデントに凹凸を持たせ「コードの塊」に読ませる。タイピングに連動して行が増える/カーソルブロックが点滅（現行の `frame` 駆動で可）。
- sakuri 作画 code_a ポーズ中の絵内モニタにも同じシンタックス行を重ねる（現行 `drawStripCodeScreen` の重ね描き領域を流用し、バー＋コード行にする。**絵そのものには手を入れない**——重ね描きは従来からある進捗表示と同じ領域・同じ手法）。
- デバッグ状態ではモニタが**ターミナル画面**に切り替わる（黒地に緑文字行＋赤いエラー行1本＋プロンプト）。状態が画面の種類で読めるのは強いダイエジェティック表現。
- **第2モニタ**: 主モニタの右に一回り小さい縦長モニタ（ターミナル/git ログ担当: 緑行＋淡青行）を追加。デュアル化はランキング4位の記号で、机クラスタの横幅は現行 116 単位内に収める（PC 配置を左寄せに再配分）。みゅけの座位・接地アンカーは不変。
- **オフィスチェアの背**（絵に進む前の手続き版）: みゅけが机にいる時、その背後（家具レイヤー③、猫レイヤー⑤より後ろ）にチェアの背もたれ（濃グレーのメッシュ面＋ヘッドレスト＋背骨1本）を描く。座位ポーズと重なって初めて「椅子に座って開発している」絵になる。歩行中・不在時は椅子だけが残る（それもオフィスらしい）。キャスター脚は接地線に小さく。
- 机上小物: キーボードのキーキャップ列（PC 前の薄い板＋ドット列、非コーディング時も机の上に残る）／モニタ縁の**付箋2〜3枚**（パステルの小四角、ベゼルに貼る）／コーヒーマグは現行 prop_coffee を維持（赤マグは温かさの橋）／卓上カレンダーは維持し、日付に赤丸を1つ追加。
- ケーブル: PC 背面から机下へ垂れるケーブル1本＋床の電源タップ（小・濃グレー）をで追加。裏側の実在感。
- 足元: ラグ → **カーペットタイル**（`#3F5267` n 系を低アルファで敷き、タイルの継ぎ目線1本）。

### 2.3 作品棚（0.12W）→ リリース棚＋技術書

- 棚枠: 木 → **スチール＋白ラミネート棚**（枠 `#718293` D 系、棚板は淡グレー）。背後の**柵は撤去**（§1.3）。棚の背後が素通しになる分、帯の透明感（R1）も上がる。

### 2.4 研究ステーション（0.47W）→ リサーチャーのデスク

### 2.6 サーバラック（0.55W・新規）→ CI/サーバ

- 空いている E スロット 0.55W に、眠っている **`prop_server` を帯へ昇格**させる。出現条件は既存アップグレード「CIマシン」所持時（研究机と同じ「進行で増える家具」の文法。密度予算 R8 の自然な増減）。

### 2.7 イーゼル（0.20W）→ 保管段ボール＋貼り紙

- イーゼルとポスターを撤去し、**ラベル付き段ボール箱の積み重ね（大小2〜3箱）**にする。最上段の箱の側面に旧ポスター絵（prop_wall_1）を「貼り紙」として小さく貼る（解放アセットの受け皿を失わない）。
- 箱には荷札（白ラベル＋黒線2本）。作品棚の箱と文法を揃えつつ、こちらは「保管/過去分」のくたびれた色味（彩度低め）で区別する。

### 2.8 トロフィー台（0.75W）

- 木の台座 → スレートグレーの台座＋表彰プレートは**額入り賞状**（白面＋金枠＋赤リボン小）として描き直す。トロフィー自体は維持。高さ・位置は現行どおり。

### 2.9 その他（小物・任意）

## 3. メニュープラン — IDE/開発ツール方向への振り切り

### 3.1 方向の決定: 「IDE ダーク（エスプレッソ・エディタ）」を採用する

評価した2案:

- **案A 現行ライト（木＋紙）の延長**: 既に sakuri から「汎用的でテーマを読めない」と判定済み。紙・木は §1 の記号体系（コード/ボード/LED）と無関係で、磨いても「可愛い経営ゲームのメニュー」にしかならない。**不採用**。
- **案B IDE ライト（GitHub Light 風: 白地＋青リンク＋細枠）**: 紙の言い換えに近く、「ドキュメント/業務ツール」に読める。モニタの光（glow）のテーゼとも戦う。**不採用**。
- **案C IDE ダーク（VS Code Dark+ 系）**: エディタは開発者の「仕事場の顔」そのもの。ダーク面にシンタックス色が乗ると、数字と状態（緑=成功/赤=バグ/黄=警告）が**診断色**として即読できる。本作は既にバグ（赤）・詰まり（警告）・RP・進捗という「診断されるべき状態」を大量に持っており、IDE の意味体系とゲームの意味体系が一致する。**採用**。

調和の設計（sakuri の猫と戦わないための3点）:
1. **ダークは「温かいダーク」にする**: ベースはスプライトパレット既存の `U #222631 / u #2F3444` 系（青寄りチャコール）を僅かに暖色側へ寄せたエスプレッソ系。純粋な VS Code グレー（#1E1E1E）より猫のクリームと喧嘩しない。
2. **猫の居場所はクリームのまま**: スタッフカードのポートレート受け（`.sc-img`）と吹き出しは `#FFF5E6` の「写真/メモの差し込み」として残す。エディタ内のサムネイル/アバターが明るいのは自然で、sakuri の絵の色を一切変えずに「額」だけが変わる。
3. **帯は温かいまま**: 帯（壁紙の上の世界）は §2 の素材転換後も段ボール・付箋・金の温かさを保つ。世界=温かいデスクトップ、道具=ダークなエディタ、という対比は実際の開発者の画面そのもので、両者はアクセント色（付箋パステル＝シンタックスパステル）を共有して繋がる。

### 3.2 トークン（現行 → 新）

```css
:root{
/* 地と面: エディタの階層 (editor < sidebar < panel の3段) */
--bg:#211F27; /* ウィンドウ地 = ワークベンチ外周 (U #222631 を暖色化) */
--panel:#2B2833; /* パネル面 = エディタ面 (u #2F3444 系) */
--panel-2:#332F3D; /* 沈んだ行・スロット・stat面 */
--tab-off:#1D1C24; /* 非アクティブタブ (エディタのタブ帯) */
--line:#4E4763; /* 枠の主色 (旧 --ink #463126 の置換: 濃スレート紫) */
--line-soft:#3B3648; /* 副枠・溝 */
/* 文字: 猫のクリームを落とした温かいオフホワイト */
--ink:#EFE7D7; /* 主文字 (W #FFF5E6 の減光) */
--sub:#A79DB2; /* 補助文字 (淡ラベンダーグレー) */
/* シンタックス = 意味色 (VS Code Dark+ を本作パレットに調和) */
--syn-blue:#6FA8DC; /* キーワード/リンク/主アクション枠 (m #578BC5 の昇格) */
--status:#46678A; /* ステータスバー地 (M: 既存パレット。VS Code #007ACC の減彩版) */
--syn-str:#F49A45; /* 文字列=橙: プライマリボタンはこの色のまま「文字列色」として再定義 (A) */
--syn-func:#F8CF69; /* 関数=金黄: pricetag・Lv・報酬 (h) */
--syn-type:#5EC8B4; /* 型=ティール: 研究/RP の副色 */
--syn-num:#B5CEA8; /* 数値=淡緑: 統計の良数値 */
--syn-green:#7BE495; /* 成功/テスト通過 (帯モニタのコード緑と同一の既存色) */
--syn-purple:#C586C0; /* 制御/RP: 研究ポイントの主色 (新規だが Dark+ 標準色) */
--red:#E5534B; /* エラー/危険 (首輪赤 H #C53333 のダーク地用昇格) */
--gold:#F1BF41; /* 実績 (Z、現行維持) */
--paper:#FFF5E6; /* 猫の差し込み専用 (ポートレート受け・吹き出し) に降格・温存 */
}
```

- 枠の物理は現行の文法（太枠 2.5–3px・硬い影・押下で沈む）を**維持**する。色だけが木→スレートに変わり、影は `rgba(0,0,0,.4)` の硬い影＋上面に `inset 0 1px 0 rgba(255,255,255,.07)` のエディタ式ハイライト。角丸も現行値のまま（IDE 化で角を鋭くしすぎると部品の「ゲーム感」が死ぬ）。
- 数値: `ui-monospace,"Cascadia Code",Consolas,"Noto Sans Mono",monospace` ＋ tabular-nums を全数値に（現行 tabular-nums の拡張）。見出し・ラベルは現行の丸ゴ系 JP スタックを維持（エディタ UI も本来サンセリフ。日本語の温かさをラベル側に残す）。

### 3.3 部品ごとの翻訳（IA・部品セットは不変）

| 現行部品 | IDE 化後の顔 |
|---|---|
| ヘッダ（木帯＋刻印タイトル） | **タイトルバー＋ステータスバー**の2段。タイトルバーは `--tab-off` 地に小さく。直下のステータスバー（`--status` 地）にリソースチップを「ステータス項目」として並べる（VS Code のステータスバーに 🪙/🔬/⚡ が並ぶ絵）。右端には **✗ バグ数（赤）/ ⚠ 詰まり（黄）** の診断表示——VS Code の問題カウンタそのもの |
| 「デスクトップに戻す」（赤い閉じる板） | ウィンドウ操作ボタン様式の ✕ 板（赤は維持。OS の閉じるボタンの記号なので IDE 化と矛盾しない） |
| フォルダタブ | **エディタのファイルタブ**: 非アクティブは `--tab-off`、アクティブは `--panel` と同色で面と一体化（現行フォルダタブの接続処理をそのまま流用）、アクティブタブ上端に 2px の `--syn-str` アクセント線。バッジ（買える/新着）はタブ右の**ドット**（VS Code の未保存 ● の文法、色は金/赤） |
| リソースチップ（通貨ピル） | ステータスバー項目: 面なし・アイコン＋等幅数字。増減の bump はステータスバー項目の一瞬の発光に |
| ボタン（板＋ベベル） | 形は維持。primary は `--syn-str`（文字列色）地に濃色文字、通常ボタンは `--panel-2` 地＋`--line` 枠、hover で面が1段明るく。disabled は彩度低下（現行文法） |
| pricetag（金の価格タグ） | 維持。金は「関数色」として IDE 内でも正当。枠は `--line` |
| fold（折りたたみ） | **サイドバーのセクション見出し**様式: 小さな大文字寄りラベル＋▸/▾ シェブロン＋区切り線。VS Code のエクスプローラ/アウトラインの折りたたみと同文法 |
| switch（板スイッチ） | 設定トグル様式: OFF は `--line-soft`、ON は `--status`→緑ノブ現行を `--syn-green` に寄せる |
| meter（ストライプバー） | トラックは `--tab-off` の溝、フィルは意味色ベタ＋現行ストライプ維持。進捗=青（エディタのプログレス）、集中力=橙、正常=緑 |
| 工場 ratestrip / 信号機図 | **CI パイプライン**様式に寄せる: 工程セルを ●─●─● の接続線つきステップにし、通過=緑✓、詰まり=赤✗、処理中=橙の回転ドット。GitHub Actions / CI の顔が本作の「工場」表示の正体に最も近い |
| hero カード（プロジェクト） | エディタの「開いているファイル」面: 大 % は等幅 31px のまま、feat チップは**付箋色**（帯ボードと同色）にして帯⇔メニューの対応を見せる |
| staffcard | 面は `--panel-2`、ポートレート受けだけ `--paper`（§3.1-2）。Lv バッジは金（関数色）維持、役職アイコン受けは `--tab-off` の溝 |
| stamp（実績） | 「バッジ/実績」様式: 取得済みは金枠＋面 `--panel-2`、未取得は彩度低下。判子の回転は維持可（遊びは残す） |
| 通知カード（return/update） | 左色帯プレートの文法を維持し、色帯を診断色に（return=金、update=青）。面は `--panel` |
| スクロールバー | エディタ式: 細め・トラック透明・つまみ `--line`（hover で `--sub`） |
| select/textarea | ダーク面＋`--line` 枠。textarea は「コードを書く場所」として等幅＋行番号色の罫に寄せる（メモ帳ではなくエディタの入力欄） |

### 3.4 メニューで「やらない」こと

- エディタの完全な再現（ミニマップ、パンくず、コマンドパレット等）はしない。あくまで**スキンと記号の借用**で、部品の形・IA・操作は現行が正。
- 文字を全部等幅にしない（日本語ラベルの可読性と温かさを守る。等幅は数字と診断表示だけ）。
- 猫の絵・吹き出し・ポートレートの色には触らない。

## 4. 実装フェーズ計画（テーマ効果 ÷ 労力 順）

### Phase 1 — メニュー IDE ダーク化★最大効果・最小労力
- §3.2 トークン差し替え＋ §3.3 の CSS 翻訳（ヘッダ2段化は既存 DOM の背景・配置変更の範囲、タブ/チップ/fold/meter/switch の色と形）。
- DOM 構造・ID・クラス・JS は無変更（MENU_REDESIGN P0 と同じ安全域）。ステータスバーの診断表示（✗バグ/⚠詰まり）は既存の表示要素の再配置で済む範囲に留め、新規ロジックは入れない。
- 完了条件: 9タブのスクショで「木と紙」が消え、ダークエディタ＋シンタックス意味色に統一されていること。猫ポートレートのクリームが差し込みとして生きていること。

### Phase 2 — 帯の「色と画面」クイックウィン
- モニタ中身のシンタックス化（主モニタ＋code ポーズ重ね＋デバッグ時ターミナル切替）。
- 机天板・棚枠・研究机の素材色差し替え（ラミネート/スチール）、柵の撤去、ラグ→カーペットタイル、棚への技術書の列、卓上カレンダーの赤丸。
- 新規スプライト不要。既存描画関数の色定数と小さな描画追加のみ。

### Phase 3 — カンバンホワイトボード化
- §2.1: ボード2種（主/ライン2）の素材と中身の翻訳。`projectBoardModel()` の算数は不変、描画関数 `drawStripProjectBoard` の差し替え。ヒット矩形・クリック導線（openProjPanel）は不変。
- 完了条件: 帯スクショで feat 付箋の列移動・詰まり赤付箋・企画 BACKLOG が読めること。1280/1600 両幅で衝突なし（現行ボードの検証条件を継承）。

### Phase 4 — 家具の追加と置換
- オフィスチェアの背（主/第2机）、第2モニタ（主=ターミナル、第2机=CI パイプライン画面）、ケーブル＋電源タップ、サーバラック昇格（`prop_server` 流用＋LED 点滅、CI 所持で出現）、イーゼル→保管段ボール＋貼り紙（prop_wall_1 流用）。
- 完了条件: 全家具出現状態の帯スクショ（1280幅）で密度・高さ予算（R5/R8）を満たし、空白 35% を割らないこと。

### Phase 5 — 絵の本格化
- 手続き描画で弱い部分（チェア、デュアルモニタ、サーバ）の専用スプライト化（生成 or みゅー作画。キャラではないので sakuri 作画でなくてよい）。
- メニューの 9-slice 枠をエディタ風フレーム PNG に（MENU_REDESIGN P2 の IDE 版）。
- 見出し・数字専用ピクセルフォントの同梱（任意）。

### 依存と順序の注意
- Phase 1 と 2 は独立に進められる（管理ウィンドウと帯で対象が別）。
- Phase 3 は Phase 2 の色体系（付箋パステル＝シンタックスパステル）を前提にするため 2 の後。
- どのフェーズでもセーブ形式・ゲームロジック・バランスには触らない（全部「見た目」の層）。帯の変更は STRIP_CANON のチェックリスト（§d）で都度照合する。
