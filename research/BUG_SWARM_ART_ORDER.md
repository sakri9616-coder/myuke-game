# 在庫バグを帯に出す — ドット絵発注書

2026-10-27 · sakuri の指示「バグは大量発生イベントでないときにも画面に出して、手動でも潰せるようにしてください。大量にバグを発生させる（一万）プレイも想定します」「自動的にパッチが当たってバグが撃破される演出も想定してください」。

在庫バグ（`S.bugStock`）を帯の地面に常に這わせ、クリックで潰せるようにする。少ないうちは1匹ずつ、増えると「群れ」の絵1枚でまとめて描く（1万匹でも描く枚数は20枚前後に抑える）。QA・デバッグで自動的に減るときは、上から「パッチ」が落ちてきてバグに貼り付き、ぽんと消える。

コードで絵を描くのは禁止なので、以下をドット絵で発注する。

## 発注リスト

すべて原寸のまま帯に等倍で置く。下端中央アンカー（地面に立つ）。上・左・右に 1px 以上の透明余白。色は `graphics/sprites.js` の既存パレットだけを使う（新色ゼロが目標）。既存の `icon_bug`（28×28、黒い縁取り `z`・頭 `K`・赤い胴 `R`）と同じバグに見えること。

| 名前 | サイズ | 内容 |
|---|---|---|
| `icon_bug_s_0` / `icon_bug_s_1` | 14×10 | 地面を這う小さなバグ（右向きの横顔、触角2本、脚3対）。2コマで脚が交互に動く。`icon_bug` の配色 |
| `icon_bug_swarm_s_0` / `_1` | 26×13 | 小さなバグが5〜6匹かたまった群れ。2コマで何匹かの位置・脚がずれてうごめく |
| `icon_bug_swarm_l_0` / `_1` | 44×20 | 15匹以上が折り重なった大きな群れ（こんもりした山）。2コマでうごめく。`_s` と同じバグの描き方 |
| `fx_patch` | 12×10 | 落ちてくる「パッチ」。水色〜白の絆創膏のような四角い当て布に小さな「+」。縁取りは濃い色 |
| `fx_bug_poof_0` / `_1` | 16×12 | バグが消えるときの煙。0 は丸い煙＋小さな星、1 は散って薄くなった煙 |
| `fx_bug_splat` | 14×6 | 手で叩いて潰れたバグ（ぺちゃんこ、脚が横に広がる）。地面に一瞬残る |

## 使い方（参考）

- 1〜12匹: `icon_bug_s_*` を1匹ずつ。QA トレイから出て地面を歩き回る。
- 13匹以上: 1匹ずつの絵は最大8匹に留め、残りを群れの絵で描く。群れの数は匹数の桁に応じて増え（13匹で数個、1万匹で12個）、100匹を超えると大きな群れ `_l` が混ざる。
- クリック: 1匹の絵なら1匹、群れの絵ならその群れが表す匹数の一部を潰す。`fx_bug_splat` → `fx_bug_poof_*`。
- 自動（QA・みゅけのデバッグ）: `fx_patch` が上から落ちてバグに貼り付き、`fx_bug_poof_*` で消える。

## 納品物

1. `graphics/env-sprites-bugs.js` — `window.MIYUKE_ENV_SPRITES_BUGS = { palette, sprites: { 名前: string[] } }`。`graphics/env-sprites-visible2.js` と同じ形式（`.` = 透明、各行は指定幅ちょうど、行数は指定どおり）。絵ごとにサイズ・アンカー・用途の1行コメント。
2. `graphics/env-preview-bugs/<名前>.png`（4倍・最近傍・#808080 の地）と `contact-sheet.png`。描画スクリプトは `graphics/render-env-preview-vis2.cjs` に倣い標準ライブラリのみ。
3. `research/BUG_SWARM_ART_MANIFEST.md` — 絵ごとに名前・サイズ・内容・使ったパレット文字・新色（あれば hex と理由）。
