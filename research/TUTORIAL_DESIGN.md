# チュートリアル導線 設計書（段階的開示 / FTUE)

sakuri さん指示: 「最初から全要素に触れる実装もよくないね、チュートリアルの導線組んでみて」
対象: `game/index.html`（v2.3.7 コード状態、2ウィンドウ化・帯プロジェクトボード B12 済み)。本書は**設計のみ**で、ゲームコードは変更していない。

設計の前提（正本ルール、本書でも不変）:

- **世界は帯だけ** (Strip Canon R11)。チュートリアルも帯が主舞台で、メニューは着脱式の管理コンソール。
- **メニューは開かない状態がニュートラルなゲームプレイ状態** (sakuri 確定原則)。導線の全ビートはメニューを開かなくても体験でき、メニュー側は「いま何が開いていて、次に何が開くか」の鏡でしかない。
- **邪魔しない・急かさない・ペナルティなし**。ブロックするモーダルは禁止。ガイドは全部スキップ可能で、終わったガイドは二度と出ない。

## 0. 現状診断（何が問題か）

新規セーブの起動直後から、9タブ・工場の9種アップグレード＋第2ライン＋引っ越し＋星屑ショップ・スタッフ5役職＋スタジオ拡張＋ご褒美・研究ティア1＋ティア2＋反復研究・依頼・クリック強化6種が**全部見えて全部触れる**。新規プレイヤーが最初の1分で直面する意思決定は数十個あるのに、コアループ（見守る→リリース→買う）はまだ1周も回っていない。

ただし経済の側は既に「最初の5分」が設計済みで、良い素材が揃っている:

| 既存の仕掛け | 実測/確定値 |
|---|---|
| 初回プロジェクト TUT=120DP＋生産 ×3.4 (firstBoost) | 初リリース 約4分（sim 両タイプ4分、帯・無操作実測 270–290秒） |
| 初回の金の魚 | 3分目までに確定出現 |
| 初コミット/フィーチャチェック | 100DP 周期、TUT は約1分ごとにフィーチャに ✅ |
| 帯の可読レイヤー | プロジェクトボード (B12)＋節目チップ `#strip-mile`（あと○DP / ⚠詰まり / 🎉リリース） |
| セリフ基盤 | `say()` の吹き出し（帯＋menu の live 反映まで配線済み） |
| タブバッジ基盤 | `updateTabBadges()`（買える物があるタブにドット/件数） |

つまり不足しているのは経済ではなく**開示の順序**だけ。本設計は価格・レート・sim 定数を一切変えず、「見せ方と触れる順番」だけを組み直す。

## 1. 参考調査（比較対象の段階的開示）

- **Kittens Game / Trimps**（CHI 2018 論文 “Playing to Wait” が “Unlocking as Usability Support” と命名）: 膨大なシステムを持つマイクロマネジメント系でも UI は少しずつ unfold し、かつ**「次のアップグレードは何で、どうすれば手に入るか」を常に可視化**する。隠すのではなく「予告する」ことが要点。本設計のシルエット＋条件ビジュアルはこの方式。
- **Antimatter Dimensions**: 開始時は実質ボタン1個（次元を買う）。Infinity → Eternity → Reality の層は「前の層を理解した頃に報酬として」現れる。新しい層は新しい通貨＋新しい判断軸を伴う。本設計のステージも「タブが増える」ではなく「**新しい動詞が増える**」単位で切る。
- **NGU Idle**: 機能（Adventure / Augments 等）はボス撃破で順に解放され、メニュー項目自体が「倒すべきボス」という条件付きで先行表示される。解放＝報酬ビート。
- **Melvor Idle**: スキルとその中身はレベル条件を明示したまま段階表示。条件が見えるから「あと少し頑張る」目標になる。
- **デスクトップペット系（Tiny Pasture / Rusty's Retirement）**: 初回は「動物＋できること1〜2個」。店の品揃えは稼ぎに連れて広がる。世界側（帯）が常に主で、管理画面は従。
- **FTUE 一般則**（NN/g の progressive disclosure、Apple/Roblox のオンボーディング指針）: ①コアループを最初に教える ②新しい動詞は1回に1つ ③必要になった瞬間に文脈で教える (just-in-time) ④経験者はスキップ可能 ⑤前倒しの長文説明を置かない ⑥コーチマークは1要素ずつ、短く、消せる。
- **フィードバック密度**: 序盤は「買える解放が 5〜15 秒〜数分おきに可視の状態変化が起きる」ことが離脱を防ぐ。本作は約1分ごとのフィーチャ ✅、3分の金の魚、4分の初リリースが既にこの密度を満たす。ステージ解放はその上に乗る大きなビートとして設計する。

## 2. ステージマップ（本設計の核）

解放の単位は**タブまたはセクション**。トリガーは全て「測定可能なゲーム内事実」（セーブ内の累計値・所持・完了フラグ）で、経過時間では解放しない（放置しても遊んでも、その人の進み方で開く）。

### Stage 0 — はじまり（新規セーブ)

- **見えるもの**: 帯の全部（みゅけ・机クラスタ・プロジェクトボード・HUD・節目チップ）。メニューは プロジェクト／設定 の2タブだけ実体。残り7タブと各セクションはシルエット（§3)。
- **唯一の動詞**: 見守る＋**みゅけをクリックして応援**。入力ブースト（自分のタイピングで進む）は帯の体験として自然に効くが、説明はしない（OS 集計の同意は Stage 1 の文脈ヒントで後述）。
- **ガイドビート**: 起動時の挨拶吹き出し（既存: 「はじめまして、みゅけだにゃ。小さい工場もよろしくね。」）→ 数秒後に目的チップが点く。
- **目的チップ**: 「🎯 最初の作品ができるまで見守ろう」＋ボードの進捗（あと○DP は節目チップが既に担うので、目的チップは**動詞だけ**を短く持つ）。
- **マイクロビート**: 初フィーチャ ✅（約1分）でボードがパルス／初バグが出たら debug ポーズ＋吹き出しで「バグは勝手に叩くから大丈夫」を体験で伝える／金の魚（3分まで）が出たら吹き出し「✨ 金の魚！クリックで捕まえられるよ」（初回だけ）。

### Stage 1 — 初リリース（トリガー: `totals.releases >= 1`)

- **解放**: 📚 作品棚 タブ／📊 統計 タブ／🏭 工場 タブの **工程アップグレード節のみ**。
- **理由**: リリースのご褒美は3つ同時に意味を持つ — 作品が棚に増えた（見る）、記録が残った（見る）、60🪙 で初めて買い物ができる（買う）。ただし新しい動詞は「買う」1つだけにするため、工場はアップグレード節に限定し、残り（ボット／第2ライン／引っ越し／星屑ショップ）は節ごとシルエット。
- **ガイドビート**: リリース演出そのものが先生になる（celebrate → 棚へ配達の小旅行 → 棚に箱が載る）。落ち着いたら吹き出し「🪙 たまったにゃ。『ひらく』→工場で道具が買えるよ」。帯の 🆕 バッジ（タブバッジ基盤を流用）を工場タブに点ける。
- **目的チップ**: 「🎯 工場で道具を1つ買おう（あと○🪙 は不足分だけ表示。キーボード 40🪙 は即買える）」。
- **文脈ヒント（1回だけ・任意）**: Stage 1 到達後のどこかで吹き出し「あんたがキーボードを打つと、あたしも速く書けるにゃ。設定の『OS全体の入力カウント』で有効にできるよ」。同意 UI への誘導はこの1回のみ。以後は設定タブの既存説明に任せる（権限リクエストは必要になった文脈で、が FTUE の原則）。

### Stage 2 — 研究（トリガー: 累計 RP ≥ 2 ＝ 2作目リリース相当）

- **解放**: 🔬 研究 タブ（ティア1のみ実体。ティア2と反復研究は前提アイコン付きシルエット — 既存の `requires` データをそのまま条件ビジュアルにする）。
- **理由**: RP が初めて「買える量」に達した瞬間に開くので、開いた画面には必ず買える物が1つある（res_plant 2RP / res_game 2RP)。「開けたけど何もできない」が起きない。
- **ガイドビート**: 吹き出し「🔬 研究ポイントが2つたまったにゃ。新しいジャンルや一人遊びが研究できるよ」。
- **目的チップ**: 「🎯 研究を1つ進めよう」。

### Stage 2.5 — 応援強化（トリガー: `totals.clicks >= 30`、未達でも `totals.releases >= 4` で自動解放）

- **解放**: 👆 応援 タブ（クリック強化ツリー）。
- **理由**: 応援クリックは Stage 0 から帯でできる動詞。その強化ツリーは「クリックを気に入った人」にだけ先に開く**発見型解放**（do → unlock の順）。最安の肉球 80🪙 は2作目前後で買える価格帯なので、解放時点で買い物も成立する。クリックしない放置型には 4作目で静かに開く（取りこぼし防止）。
- **ガイドビート**: 解放時に吹き出し「👆 よく応援してくれるね。応援タブでクリックが強くできるよ」。自動解放時は吹き出しなし（バッジのみ）。

### Stage 3 — 仲間（トリガー: `totals.coinsEarned >= 220` = 最安の雇用が買える累計収入）

- **解放**: 👥 スタッフ タブ（雇用＋育成＋スタジオ拡張。ご褒美節はシルエットのまま §3）／工場の **子ねこボット** カード。
- **理由**: 「同僚」というテーマで雇用とオートメーションを1ステージに束ねる。sim では初雇用・初ボットとも 1〜2日目で、この順序と一致する。
- **予告の仕掛け**: 未雇用の毛柄の猫が帯を横切る「訪問猫」は既にアンビエントとして実装されている — Stage 3 未満ではこれが**解放のティーザー**として機能する（追加実装なし、意味だけが変わる）。解放の吹き出しは「🐱 さっきの猫、雇えるようになったにゃ」。
- **目的チップ**: 「🎯 スタッフを1人雇おう」。

### Stage 4 — 依頼（トリガー: `totals.hired >= 1`、未達でも `totals.releases >= 5` で自動解放）

- **解放**: 📮 依頼 タブ。
- **理由**: 依頼は「次作品のジャンル指定＋ボーナス」という目標レイヤーで、生産が安定してから意味を持つ。依頼データ自体は起動時から生成済み（ジャンルプールは研究解放分のみに制限済み＝抜け道なし）なので、解放と同時にボードは既に埋まっている。
- **ガイドビート**: 吹き出し「📮 お客さんから依頼が届いてるにゃ。受けると次の作品がそのジャンルになるよ」＋タブに件数バッジ（既存基盤）。
- **目的チップ**: 「🎯 依頼を1つ受けよう」。

### Stage 5 — 第2ライン（トリガー: 研究 `res_line2` 完了）

- **解放**: 工場の **第2ライン節**（建設ボタン＋ライン2のジャンル指定）。帯側は建設後に第2机＋ボード2が出現する既存演出がそのまま解放ビートになる。
- **理由**: ゲーム本体が既に `res_line2` を建設のハードゲートにしているので、導線はそれを**先行表示**するだけ: Stage 2 以降、工場の第2ライン節はシルエットで「🔬 第2ラインの設計（研究）」と「🪙 1,500」の2条件をビジュアルで見せ続ける。sim の建設は 4〜6日目 — 研究完了から建設費が貯まるまでの期間が、このゲーム最長の「目標期間」になる。
- **ガイドビート**: 研究完了の瞬間に吹き出し「🏭 第2ラインが設計できたにゃ！あとは建設費 1,500🪙」。
- **目的チップ**: 「🎯 第2ラインを建設しよう（🪙 あと ○○)」。

### Stage 6 — 引っ越し（トリガー: `prestigePreview().gain >= 5` = 星屑5個ぶん到達、sim で 8〜9日目）

- **解放**: 工場の **引っ越しカード＋星屑ショップ節**（それまでは ⭐＋「？？？」の深いシルエットで折りたたみ内に格納 — 存在の気配だけ）。
- **理由**: プレステージは「やらなくてもいい」周回軸なので、解放しても目的チップは**立てない**（急かさない原則）。吹き出しも1回だけ、断定調にしない: 「⭐ だいぶ星屑がたまったね。引っ越しすると最初からだけど、ずっと強くなるよ。工場タブに置いといたにゃ」。
- **ここでチュートリアルは卒業**。以後残るのは解放済みタブ内の深部（研究ティア2・反復研究・ご褒美・星屑レベル制特典）で、いずれも各タブ内のシルエット＋条件表示が案内を続ける（§3 の節内ルール）。新しいステージは増やさない。

## 3. ガイド面の仕様（正本に沿った出し方）

### 3.1 帯（主舞台）

- **吹き出し `say()`** が唯一の「声」。解放ビートは全部ここから出す。1度に出すガイド吹き出しは1つまで（既存の表示 4.2 秒を流用し、ガイド用は完了 or 次の通常セリフに譲るまで保持しない — 通常セリフに上書きされたら再送はしない。「見逃し」は許容する設計。重要な解放はタブバッジとシルエットの変化が恒常的に残るので、吹き出しは飾りで本体ではない）。
- **目的チップ `#strip-quest`**: 節目チップ `#strip-mile` の隣（HUD 左端クラスタ）に新設する兄弟チップ。文面は「🎯 ＋ 動詞1つ ＋ 不足分だけ数値」。完了した瞬間に 🎉 系の一文へ切り替わり数秒で消える。Stage 6 以降と、目的のない時間帯は非表示。帯の美学を壊さないため、節目チップと同じフェード作法（変化直後だけ濃く、後は 0.6 に薄れる）。
- **解放の祝い**: リリース時の紙吹雪・配達の小旅行といった既存の帯演出が解放ビートを兼ねる。新規の祝いは追加しない（第2ライン建設時の机出現など、世界の変化自体が報酬）。帯にモーダル・パネル・暗転は**置かない**。

### 3.2 メニュー（鏡）

- **ロック中タブは消さず、シルエットで出す**（Kittens Game 方式）: タブは 🔒＋アイコンをグレーにし、クリックすると本体の代わりに**ロックパネル**を出す。ロックパネルは文字で説明せず: 大きなシルエット絵（そのタブの代表スプライト/アイコンを暗く表示）＋**条件をビジュアルで**（対象リソースのアイコン＋進捗バー＋現在/必要数。例: スタッフタブなら 🪙 バー 132/220、研究なら 🔬 0/2、第2ライン節なら 🔬研究アイコンと 🪙 0/1500 の2本バー）＋みゅけの一言（吹き出し文の流用）だけ。
- **タブ内の節シルエット**: 解放済みタブでも未解放の節は、見出しバーだけを暗く出し、条件チップを右に付ける（既存の `foldSec` 基盤の見出しを流用し、開けない fold として描く）。対象: 工場=ボットカード (Stage 3)、第2ライン節 (Stage 5)、引っ越し/星屑節 (Stage 6)、スタッフ=ご褒美節（条件: 累計コイン 5,000 — 終盤シンクなので条件バー付きで常時シルエット、Stage 3 以降に表示開始）、研究=ティア2各カード（前提研究のアイコン＋済/未済 ✅/🔒、既存 `requires` の描画を条件ビジュアルに格上げ）、反復研究（条件: ティア1全完了）。
- **🆕 バッジ**: 新しく開いたタブには初回訪問まで 🆕 を付ける（`updateTabBadges` の枠組みに追加ルールとして）。開くべき場所が帯からもメニューからも分かる。
- **設定タブは最初から全部開いている**（音・入力カウント同意・セーブ管理はプレイヤーの権利であって、ゲームの解放対象にしない）。ここに §4 のスキップ/リセットも置く。

### 3.3 やらないこと

- 起動直後の説明モーダル・利用規約式の連続コーチマーク・メニュー側への誘導ポップアップ連打。
- 時間経過だけでの解放（放置で勝手に開くと「報酬」にならない）。
- 解放を理由にした価格・レートの変更（sim ゲートは現行値を正とする）。

## 4. 既存セーブと例外のルール

### 4.1 グランドファーザリング（既存プレイヤーは何も失わない）

ステージは保存された**事実**から導出できる。マイグレーション時は保存済みチュートリアル状態が無ければ `deriveStage(S)` で初期化し、導出されたステージまでの `seen` は全部 true にする — つまり**現行プレイヤー（sakuri さんのセーブ含む）は起動した瞬間に卒業扱いで、チュートリアルの気配すら出ない**。

導出表（事実 → 最低ステージ）:

| 事実 | 導出ステージ |
|---|---|
| `totals.releases >= 1` | ≥ 1 |
| 研究を1つでも所持 or `totals.releases >= 2` | ≥ 2 |
| `clickUp` を1つでも所持 | ≥ 2.5 |
| `totals.hired >= 1` or スタッフ在籍 | ≥ 3（かつ ≥ 4) |
| `totals.releases >= 5` | ≥ 4 |
| `S.research.res_line2` | ≥ 5 |
| `S.line2.unlocked` | ≥ 5（建設済みは当然） |
| `S.prestiges >= 1` or `S.dustTotal >= 5` | 卒業 (6) |

### 4.2 「所持がロックに勝つ」原則

ロック判定は常に `locked(feature) = stageBelow(feature) && !ownsAny(feature)` とする（例: 何らかの事情でステージが低くても、既に雇ったスタッフがいるセーブでスタッフタブがロックされることは決してない）。これにより:

- リセット（§4.3）しても**進行は一切巻き戻らない**。ガイド文だけが若返る。
- プレステージで `staff=[]` 等がリセットされても、チュートリアル状態はリセット対象に**含めない**（`doPrestige` の初期化リストから `tut` を明示的に除外する。第2ラン以降は卒業済みのまま — 引っ越し後の再教育はノイズでしかない）。

### 4.3 スキップとリセット（設定タブに常設）

設定タブ（常時開放）に「🎓 チュートリアル」行を1つ追加:

- **「ガイドを全部ひらく」**: `tut.skipped = true`、stage = 卒業。以後ロックも目的チップも一切出ない。
- **「ガイドを最初から見直す」**: `tut.seen` を全 false に戻し stage を `deriveStage(S)` で再導出（所持がロックに勝つので、実質「これから開くもの」のガイドだけが復活する）。吹き出しの再演用で、ペナルティ・巻き戻しなし。
- どちらも確認モーダルなし・即時反映・何度でも切替可能。

### 4.4 完了したガイドは永続的に消える

各ビートは `seen` フラグで1回性。ステージが上がる条件を満たした瞬間にビートは「消費」され、セーブを跨いでも再演しない。目的チップは現ステージの未完了目的だけを出し、完了で即座に次へ（または消える）。

## 5. データモデル

追加は `S.tut` の1オブジェクトだけ（additive、load() の既定値マージで旧セーブに自動補完される既存パターンに乗る）:

```js
tut: {
  stage: 0,            // 数値ステージ (0,1,2,2.5 は内部値 25 等の連番にすること。
                       //  実装時は STAGE = { START:0, RELEASE:1, RESEARCH:2, CLICK:3, STAFF:4, REQUEST:5, LINE2:6, PRESTIGE:7 })
  seen: {},            // ビート単位の既演フラグ { s1_buy:false, input_hint:false, fish_hint:false, ... }
  skipped: false       // 全部ひらく を押したか
}
```

- **置き場所**: `S` の直下（スナップショットで menu に自動で届く — 2ウィンドウ化により、ロック描画は viewer 側のレプリカ `S.tut` を読むだけで済み、プロトコル追加は不要）。保存・書出/読込（セーブ IO）にも自動で含まれる。
- **マイグレーション**: `load()` のマージ後、`S.tut` が「新規作成された既定値」だった場合は `deriveStage(S)` で stage を引き上げ、`seen` を導出ステージ分まで true で埋める。新規セーブは `hadSave=false` の経路で stage 0 のまま（導出しても事実が無いので 0 になる — 同じ関数でよい）。
- **進行チェックの置き場所**: 既存の 1 秒 tick の末尾に `tutCheck()` を1つ（述語は累計値の比較だけなので毎秒でも無視できるコスト）。加えて解放の即時性を上げるため、トリガー行動（`releaseProject` / `buyUpgrade` / `buyResearch` / `hireStaff` / 応援クリックのカウンタ加算点）からも同じ関数を呼ぶ。ステージが上がったら: `say()` でビート＋目的チップ差し替え＋タブバッジ更新＋`bumpRev()`（スナップショット即時送信は say 経由で既にある）。
- **帯チップの描画**: `stripMilestoneText()` の隣に `stripQuestText()` を置き、既存のフェード作法・表示条件（帯モードのみ）を共有する。

### スモークテストでの検証方法（Phase F を新設する想定）

既存ハーネス（ブラウザ フル/帯の2コンテキスト＋Phase E の偽イベントバス）の延長で:

1. **新規セーブ**: 起動直後にロック集合が Stage 0 の定義通り（タブのロッククラス、ロックパネルの条件バー値、工場に第2ライン節の実体が無いこと、設定だけ全開）。
2. **段階進行**: セーブを操作して各トリガー事実を満たすたびに、対応ステージへ**ちょうど1段だけ**上がり、対応セクションの実体（購入ボタン等）が現れること。飛び級（例: いきなり `prestiges=1` のセーブ）では導出ステージまで一気に上がり、途中のビートが連打されないこと。
3. **ベテラン fixture**: 既存の Phase A2/A4 と同方式で「作品30・スタッフ在籍・研究複数・引っ越し1回」のセーブを仕込む → 導出=卒業、ロック DOM ゼロ、目的チップ非表示、`seen` 全埋め。
4. **スキップ/リセット**: スキップで全ロック解除＋チップ消失／リセットで「所持がロックに勝つ」が効く（スタッフ在籍セーブでリセットしてもスタッフタブは開いたまま）。
5. **プレステージ跨ぎ**: `doPrestige()` 後も `tut.stage` が卒業のまま変わらないこと。
6. **viewer 側**: Phase E のバス経由でスナップショットを受けた viewer が、owner と同じロック集合を描くこと（viewer は tick を回さないので、ステージ進行は owner の snapshot だけで伝播することの確認）。

### バランス sim への影響

- **定数は一切変更しない**ので、sim のゲート（初リリース ≤ 約5分／30日総量アクティブ ≥ 放置 ×1.3／7日目以降 0 リリース日なし）は無影響。ロックは表示と導線だけの話で、経済の「買える時刻」は §0 の表のまま。
- むしろ検証すべきは逆方向: **導線が sim の想定購入時刻より遅れてはいけない**。トリガーは全て「sim がその購入を行う瞬間」以前に発火するよう置いた（キーボードは Stage 1 の 60🪙 時点で買える／雇用は累計 220🪙 到達＝sim の初雇用と同時／第2ライン節は `res_line2` 完了＝建設の前提そのもの／引っ越し節は gain ≥ 5 ＝ sim の「実行可能」判定と同点）。実装時に sim へ `firstHireDay` 等の既存マイルストーンと導線トリガーの対応をコメントで1行残すこと。
- 唯一の行動変容リスク: Stage 0 で工場が見えないため、初リリース前に「下見」できない。だが初リリース前は所持金 0 で何も買えないので実害はない（シルエットの条件バーが下見の代わりをする）。
