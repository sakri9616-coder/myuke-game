# STRIP CANON RESEARCH — デスクトップマスコット帯の設計文法（タイトル横断）

目的: 「Strip Canon」リファクタ（部屋シーン廃止／帯が唯一の世界／家具で空間演出／管理はパネルのみ）の実装根拠。
方針: **正本は特定タイトルではなくジャンル形式そのもの**。以下は9タイトル横断の合意（コンセンサス）を主軸にし、タイトル間で割れる点は「バリエーション」として明記する。オーナー参照作『デスクトップ小動物牧場』はその一例（= Tiny Pasture の日本語版タイトル、CaveLiquid、2025-02-18発売）として扱う。

我々の帯の前提（現行実装）: 仮想座標 120 単位（STRIP_H）、地面 y = 下端−4、ウィンドウ実高 210px（スケール 1.75）、みゅけ 48×40 を ×2 = 96×80 単位で描画（帯高の 2/3）、机ゾーン中心 = 幅の 30%、HUD チップは右下。

## (a) タイトル別所見

### 1. Tiny Pasture（= デスクトップ小動物牧場 / 動物欄：桌面牧场、CaveLiquid）
- 画面下の帯に動物が歩き回る放置牧場。**帯の長さと位置はドラッグで自由調整**でき、画面下でなくても置ける。
- 帯は原則**透明背景**。レビューが繰り返し評価するのは「帯全体をベタ塗りバーで覆う他作と違い、透明で作業の邪魔にならない」点。
- 家具・小物は帯の中に実在する: 装飾として **植物・切り株・椅子・柵（フェンス）** が購入配置でき、魔法施設（自動給餌・清掃、ミステリーカーテン=繁殖用カーテン、Cuckoo House 等）も帯上の「施設」として置かれる。
- 管理UI: **ショップはメイン画面右側セクション**に常駐するパネル型。新規動物はそこで買う。個体ステータス（Health / Fullness / Stored Earnings）は**動物を右クリック**で見る。成長ゲージは**動物の頭上にフロート表示**される一時バー（常時HUDではない）。
- コレクション = 動物そのものが帯に並ぶこと自体＋ショップ一覧。背景は4種切替可能（ただし「部屋」ではなく空・野原系の情景）。
- 出典: https://www.gamespress.com/nl/The-Adorable-Little-Critters-Have-Arrived-Tiny-Pasture-Launches-Today- / https://godotengine.org/showcase/tiny-pasture/ / https://comicbook.com/gaming/news/idle-steam-game-tiny-pasture/ / https://www.linegames.org/news/z/view-L3VubG9sby1hbGwtYW5pbWFscy1pbi10aW55LXBhc3R1cmUtYS1jb21wbGV0ZS1ndWlkZS8 / https://www.taptap.cn/app/750425

### 2. Rusty's Retirement（Mister Morris Games）
- 画面下（または横）の帯で営む放置農業。帯は**土の地面帯（ソイルストリップ）が全幅に描かれる不透明型** — 対極のバリエーション。農地プロットが帯の内容そのものなので地面が要る。既定の高さは約150pxとのガイド言及あり、ズーム（N/Mキー）で帯の見かけサイズを可変。
- レイアウト文法は**グリッド**: 作物プロット・家・貯蔵庫・バイオ燃料コンバーター・各種ボットステーションがマス目に整列。Rusty の家は貯蔵庫兼用でランドマーク。建物は「移動のみ可・撤去不可」のものもあり、配置が恒久的。
- 管理UI: **帯の右端にアイコンレール**（メニューは右側に「really tight」に詰まっている）が常駐し、建物(2)・ショップ・統計(8)・設定（歯車、最下段）等のパネルがレールに隣接して開く。通貨（Spare Parts / Biofuel）はパネル側に集約。ヘルプ「?」は設定の下に常時。
- Focus Mode: 生産速度を約半分に落とす「邪魔しない」ための公式機能。作業中は遅く、という速度そのものを設定で落とせるのが要点。
- 出典: https://rustys-retirement.fandom.com/wiki/Buildings / https://rustys-retirement.fandom.com/wiki/Statistics / http://gameskinny.com/?p=180906 / https://www.gameskinny.com/tips/rustys-retirement-what-does-focus-mode-do/ / https://Www.Charlieintel.com/games/rustys-retirement-focus-mode-explained-how-to-enable-321716/ / https://www.ofzenandcomputing.com/rustys-retirement-guide/

### 3. Weyrdlets（Weyrdworks）
- ペットは**デスクトップ全域を自由に歩く**（帯に縛られない）。掘り掘りで資源を集める。
- 家具・部屋は **別ウィンドウの「島（ホーム）」シーン側**に存在する — つまり「デスクトップ＝ペットだけ、家具は窓の中」という分離型。**我々の正本（部屋廃止）とは逆の解**であり、バリエーションとして記録する。採用するのは同作の「ペット側には家具も壁も置かない」という潔さのみ。
- 生産性ツール（ポモドーロ・ToDo）はデスクトップ側にも出せる小物ウィジェットとして提供。
- 出典: https://store.steampowered.com/app/2366060/Weyrdlets / https://weyrdworks.itch.io/weyrdlets

### 4. Desktop Farm（voxel、Steam app 1357610）
- 農場を**壁紙として**表示する全画面型の極端例。実時刻連動の昼夜、他ゲーム中は自動ポーズ、Windows起動と同時開始。「画面下帯」ではなく壁紙置換なので帯文法の参考にはならないが、「常駐物はユーザーの作業リズムに干渉しない」が売り文句の中心である点は全タイトル共通。
- 出典: https://store.steampowered.com/app/1357610

### 5. Desktopia（village sim）
- 中世村が**画面下に沿って**発展する。建物が帯の中に立ち並び、村人が歩く。「帯の中に建物のシルエットが横に連なる」ことで場所感を作る型で、建物の高さは帯高の大部分を使う。管理は大局判断（city-builder 式）をパネルで行う。
- 出典: https://store.steampowered.com/app/2018130/

### 6. Shimeji-ee（ジャンルの祖型）
- キャラは**単独の小ウィンドウ**として存在し、画面下端・タスクバー・ウィンドウの縁を歩き、窓の上に座り、登り、落ちる。地面も小物も背景も**一切描かない** — デスクトップそのものが地形。
- クリックはキャラ本体にだけ当たる（キャラ以外の場所は素通り）。掴んで投げる等の直接操作が中心。標準スプライトは 128×128px 級で、帯型ゲームのキャラより相対的に大きい（=主役はキャラ単体）。
- 教訓: 「場所」は描かなくても成立する。帯型に降ろす場合、キャラの足元処理（接地と影）だけが地形の最小単位。
- 出典: https://ladybug-lane.neocities.org/other/screenmates

### 7. Desktop Mate（infiniteloop）／Sill Cats・Sill Dogs（SQOOL）／Desktop Mascot Engine
- Desktop Mate: 3Dキャラが**ウィンドウの上に座る**。家具・部屋なし。使わない時は画面端に静かに退避する「tuck away」が公式に謳われる — 邪魔しない設計の明文化。
- Sill シリーズ: ピクセル犬猫がウィンドウ上を歩きジャンプし、カーソルに反応。「作業の邪魔にならない機能」を実装していることを売りにする。
- 共通項: マスコット型は全て「キャラ＋（せいぜい）座り先」で、**帯に家具を置くのは経営・収集型（Tiny Pasture / Rusty's / Desktopia）だけ**。我々は経営型なので家具あり側に属する。
- 出典: https://store.steampowered.com/app/3301060/ / https://sqool.net/news/dreamnews/archive/20260924-833593.html

### 8. Little Petsville Desktop / Desktop Pasture（Low Poly）
- Petsville: 「メニューは最小限の画面占有。**ほとんどのオブジェクトはワールド空間にあり直接触れる**」を特徴として明記 — 管理をパネルに逃がしすぎず、帯上の物自体を触らせる設計。
- Desktop Pasture: 底辺配置＋装飾＋背景切替＋Workshop。背景を持つ型（ただし情景背景であり部屋ではない）。
- 出典: https://store.steampowered.com/app/4343200/Little_Petsville_Desktop/ / https://store.steampowered.com/app/3516640/Desktop_Pasture/

## (b) 蒸留した設計ルール（我々の帯への適用値）

座標は全て仮想単位（帯高 120、地面 G = 116）。CSS px 換算は ×1.75。

- **R1 地面は「線」であって「面」にするな（透明型の合意）**
  マスコット帯の多数派（Tiny Pasture / Weyrdlets / Shimeji / Desktop Mate / Sill）は帯背景を描かない。Rusty's と Desktop Farm の地面帯は「農地グリッド／壁紙そのものが内容」の場合に限る。我々はローミング型＋経営型のハイブリッドなので **土帯は敷かない**。接地は (i) 全接地物に共通の接地影、(ii) 家具クラスタの下だけに敷く薄い「足元ライン／ラグ」まで。帯の上端に水平な背景帯・壁紙帯を引くのは禁止。
- **R2 単一ベースライン**: 全ての足・家具脚・影は同じ G に揃える。奥行きは作らない（複数レーン禁止）。歩行キャラは常に家具の「手前」を通る（描画順で表現、位置では表現しない）。
- **R3 描画順（固定）**: ① 接地影・足元ライン ② 背面小物（柵セグメント・棚など壁付け相当） ③ 家具本体 ④ 運搬物・一時オブジェクト ⑤ キャラ ⑥ 吹き出し・フロート ⑦ HUDチップ。この順序を崩すと「キャラが家具にめり込む／背後に隠れる」事故になる（Shimeji の単独ウィンドウ方式が問題自体を回避していた点に倣う）。
- **R4 接地影の統一様式**: 楕円、幅 = スプライト幅 ×0.8、高さ 5–7 単位、色 rgba(50,35,25,0.20) 前後、全接地物で同一。浮遊物（鳥・浮遊エフェクト）以外は影なし禁止。「影がある = 地面に立っている」の一貫性が場所感の正体（壁なしで場所を作る最小装置）。
- **R5 高さ予算**: 家具の最高高さ ≤ 帯高の 75%（90 単位）。主役キャラ（80 単位）より高い家具は棚・家クラスの「ランドマーク」1種のみ許可し、それも 90 単位まで。装飾小物 ≤ 40 単位。背面物（柵・立て看板）≤ 28 単位。吹き出し領域（上部 約30 単位）には恒常物を置かない。
- **R6 スケール文法**: キャラ : スタッフ : 小物 = 既存仕様 48:32:24 を維持。家具は「キャラが使う物」はキャラ基準（机+PC = みゅけ座位で届く高さ ≈ 55–65 単位）、「置く物」はそれ以下。建物クラス（Desktopia 型の大きなシルエット）は我々の帯高では採用しない（帯が“街”ではなく“机まわり”のスケール感で統一）。
- **R7 ゾーン制レイアウト（幅に対する比率で固定、px 直書き禁止）**
  帯幅 W に対し、家具は固定ゾーンにのみ置く。ゾーン間は必ず歩行・空白の「呼吸」を残す。
  | ゾーン | 中心 | フットプリント上限 | 内容 |
  |---|---|---|---|
  | A 主机 | 0.30W | 0.11W | 机+PC（既存 stripDeskCX と一致） |
  | B 作品棚 | 0.12W | 0.08W | 棚家具＋作品ボックス |
  | C 研究机 | 0.47W | 0.07W | ミニ机＋本（研究員在籍時） |
  | D 第2机 | 0.63W | 0.11W | 第2ライン机+PC |
  | E 装飾スロット | 0.20W / 0.55W / 0.75W | 各 0.04W | 解放型の小家具（看板・鉢・トロフィー台） |
  | HUD 予約 | 0.86W–1.0W 右下 | — | 家具配置禁止（既存 HUD チップ域） |
  幅が広いモニタではゾーン間隔が広がるだけで、家具を増やさない（Rusty's はプロットを増やして埋めるが、それは不透明グリッド型の文法。透明型の多数派は「広さ = 余白」）。
- **R8 密度予算**: 幅 1000px あたり主要家具（机・棚クラス）≤ 2.5 個、小物・装飾 ≤ 4 個、歩行キャラ ≤ 6 体。主要家具のフットプリント合計 ≤ 帯幅の 45%、**最低 35% は家具のない空白**を常時確保する。Tiny Pasture の「スカスカさ」が称賛され、Rusty's の「整然とした満杯」が許されるのはグリッド規律あってこそ — 我々はグリッドを持たないので密度は Tiny Pasture 側に寄せる。
- **R9 場所感は「クラスタ＋小道具」で作る**: 壁の代わりに (i) 家具の寄せ集め（机+PC+マグ+棚が一つの“仕事場”として読める近接配置）、(ii) ゾーン背後の短い柵セグメント or 足元ラグ（ゾーン幅+20% まで、帯全幅に引かない）、(iii) 共通の影。背面に大きな面（壁・ボード・背景パネル）を立てるのは「部屋の変形」なので禁止。例外的に許される背面物は高さ 28 単位以下の「立て看板・イーゼル・卓上カレンダー」級のみ。
- **R10 HUD と進捗は帯に最小、数字はパネル**: 帯に常時置くのは通貨チップ1個＋開く/隠す＋節目チップまで（既存仕様が合意形）。進捗の第一表示は **ダイエジェティック**（モニタ内バー、成長バーが頭上に一時フロート等、Tiny Pasture / Rusty's の作物の実例）にし、正確な数値・バー一覧はパネルへ。帯に常時の細いプログレスバーを横断させるのは禁止（帯を「UI のバー」に見せてしまう）。
- **R11 管理パネルは帯に隣接して開く**: Rusty's の右端レール＋隣接パネル、Tiny Pasture の右側ショップが合意形。我々の「ひらく」管理ウィンドウはこの拡大形として正当（別ウィンドウ自体は合意範囲）。ただし管理側に第二の「シーン」を描かない — パネルはリスト・グリッド・数値のみ（Weyrdlets の島シーンは“やらない”側のバリエーションとして明示的に不採用）。
- **R12 クリックの当たりは「見えている物」だけ**: 空白地帯はデスクトップへ素通し（Shimeji のキャラ単独ウィンドウ、我々の動的ヒットゾーンが合意形）。家具もヒットゾーンに含め、棚クリック→作品棚パネル等の「物から管理へ」の導線を持つ（Petsville の「ワールド空間の物を直接触る」原則）。帯の全面矩形でクリックを奪うのは全タイトル共通の禁忌。
- **R13 コレクションは「帯に実物、パネルに目録」**: 完成品は棚家具に実物として積み上がり（見える成果）、パネルの作品棚タブは名前・ハイライトの目録に徹する。両方を「一覧UI」に寄せると帯が死ぬ（逆に帯だけだと検索性が死ぬ）— 二層が合意形。
- **R14 速度と静けさの設定を持つ**: Focus Mode（Rusty's）や退避（Desktop Mate）のように、「邪魔しない」ための公式の逃げ道（集中モード/隠す/音OFF既定）を必ず用意する。我々は実装済み（かくす・帯音OFF既定）なので維持確認のみ。

## (c) 家具移行スペック（部屋シーンの各要素の行き先）

仮想単位・比率は (b) の R7 に従う。全家具は接地影つき (R4)、ヒットゾーン登録 (R12)、アンロック/建設状態は既存セーブキー流用。

1. **主ワークステーション（現・机ゾーン）** — ゾーン A（中心 0.30W）。現行の机+prop_pc 配置をそのまま正本化。机上に coffee（既存 prop_coffee）を常設小物として追加し「仕事場クラスタ」(R9) を完成させる。みゅけの code ポーズ中は従来どおり絵内モニタが主、机上 PC は隠す（既存仕様維持）。足元に幅 150 単位・高さ 4 単位のラグ（最淡色）を敷きクラスタの範囲を示す。
2. **作品棚** — ゾーン B（中心 0.12W）。prop_shelf（40×28、×2 = 80×56）を G に接地。作品ミニボックスは棚板の上段・下段に既存ルール（min(総リリース数, 枠数)、最新作は金枠グロー）で積む。棚の背後に高さ 24 単位の柵セグメント（幅 100 単位）を R9 の背面物として置いてよい（任意・飾り）。クリックで管理ウィンドウの作品棚タブを開く。棚が帯左端に寄ることで「成果は左、仕事は中央、拡張は右」という読み順を作る。
3. **研究ステーション** — ゾーン C（中心 0.47W）。小型机（幅 ~64 単位）＋本の山（16×16 級 ×2–3）＋植木鉢。研究員が雇われた時のみ出現（不在ならゾーンは空白 = 密度予算の自然な増減）。研究員の待機位置はこの家具の前面（R2: 手前を通る原則の例外として「持ち場に立つ」場合は家具の真横・前面オフセット 6 単位まで）。
4. **第2ライン机** — ゾーン D（中心 0.63W）。主ワークステーションの小型版（机+PC、幅 0.10W）。第2ライン建設後に出現。ライン2担当の視覚表現はこの机に集約し、部屋時代の「第2ラインの机とコンベア」は帯では再現しない（コンベアはパネルの信号機図に一本化 — R11）。机のモニタにもライン2の進捗をダイエジェティック表示（主モニタと同じ流儀、R10）。
5. **壁飾りの家具化** — 旧 prop_wall_1/2/3（ポスター/カレンダー/表彰プレート）の解放状態キーはそのままに、帯では以下へ変換:
   - ポスター → **立て看板/イーゼル**（ゾーン E 0.20W、高さ 26 単位）
   - カレンダー → 机 A の脇に置く**卓上カレンダー**（高さ 14 単位、クラスタ内小物として扱い独立ゾーンを使わない）
   - 表彰プレート → **トロフィー台**（ゾーン E 0.75W、高さ 30 単位の台＋トロフィー）
   星屑ショップの「棚の星飾り」は棚 B の天板に載る小物として統合（独立家具にしない）。
6. **おかえり儀式の帯ステージング** — みゅけは机 A の前で sleep アニメ（既存 sakuri sleep、600ms/枚）→ 起床バブル。あらすじカードは管理ウィンドウのバナー（現行 DOM）のみ、帯側はバブル1行に圧縮（R10: 帯にカード状UIを持ち込まない）。
7. **信号機・工程表現** — 部屋のライン描画は廃止。工場パネル内の図（5工程ランプ＋バッファバー＋詰まりチップ）に一本化し、帯側は R10 の範囲で「詰まり時は節目チップが ⚠ 表示に変わる」だけに留める。
8. **植物 prop_plant 等の既存小物** — ゾーン E の装飾スロット専用に格下げ（勝手に増殖させない）。同時に帯に置ける装飾は最大 3 スロットまで (R8)。

移行時の不変条件: セーブ互換（additive のみ）、動的ヒットゾーンの「空白は素通し」を全家具追加後も維持、帯ファーストの報告用スクリーンショットは 1280 幅（家具全出現状態）と空白多めの初期状態の2枚で確認する。

## (d) アンチパターン・チェックリスト（ビルドレビュー用）

- [ ] 帯の背後に壁・床・窓・部屋状の面が描かれていないか（最重要・正本違反）
- [ ] 全幅に渡る土帯／背景帯／グラデーション帯で「バー」に見えていないか（R1）
- [ ] 家具・キャラの足元 y が単一ベースラインからずれていないか（R2）
- [ ] 描画順が 影→背面物→家具→運搬物→キャラ→吹き出し→HUD を守っているか（R3）
- [ ] 影のない接地物、または影の様式がバラバラな物がないか（R4）
- [ ] 家具の高さが 90 単位（帯高の75%）を超えていないか／吹き出し域に恒常物がないか（R5）
- [ ] 家具が比率ゾーン外に px 直書きで置かれていないか（R7）
- [ ] 家具フットプリント合計が帯幅の 45% を超えていないか／空白 35% を割っていないか（R8）
- [ ] 場所感を「大きな背面パネル」で作ろうとしていないか（R9、看板級は可）
- [ ] 帯に常時表示の数値・横断プログレスバー・カード状UIが増えていないか（R10）
- [ ] 管理パネル側に第二のシーン（部屋・島・ジオラマ）を描いていないか（R11）
- [ ] 空白地帯のクリックがデスクトップに素通りするか／家具に正しいヒットゾーンがあるか（R12）
- [ ] コレクションが「帯の実物」と「パネルの目録」の二層になっているか（R13）
- [ ] 新要素が「邪魔しない逃げ道」（隠す・静音・集中）を壊していないか（R14）
- [ ] 特定タイトル（例: 牧場作の柵や背景）の意匠を、ジャンル合意でないのに正本としてコピーしていないか
