# メニュー刷新仕様 『みゅけ、きょうも開発中』管理ウィンドウ

目的: 「ひらく」で開く管理ウィンドウを「HTMLページの残り物」から「ゲームのメニュー」に変えるための、出典付きリサーチ＋実装可能な仕様。
前提（正本の制約）: 管理側はパネルのみ・第二のシーンは描かない（STRIP_CANON R11）。DOM は維持する（Tauri に同梱される単一 HTML が出荷形態。フレームワーク導入はしない）。軽量・オフライン完結・日本語UI。帯（ストリップ）の描画には一切触らない。
現行の対象コード: `game/index.html` の `<style>`（約120行）と、ヘッダ／タブ（プロジェクト・スタッフ・工場・応援・作品棚・依頼・研究・統計・設定）／`.panel` 配下のDOM。

---

## 1. 参照リサーチ所見

### F1. 「ゲームのメニュー」の第一印象は“額縁”で決まる（Stardew Valley）
実画面で確認: Stardew のメニューは「木の板そのもの」が窓。太い木枠＋内側に一段沈んだ濃いパネル面＋葉飾りの縁取りで、**面が2階層（外枠／内面）**になっている。インベントリ等のセルは内面に埋め込まれたスロットで、各セルに内影がある。閉じるボタンは赤い「×」の小さな物理ボタンとして枠の角に乗る。右上の時計・所持金も同じ木枠のチップに入っている。
→ 要点: **「白い紙に線を引いた」のではなく「素材の板に部品がはまっている」**。枠・内面・スロットの3層構造がウェブ感を消す最大因子。

### F2. ナビは“ピル”ではなく“板ボタン”の列（NGU Idle）
実画面で確認: NGU Idle は左列に FEATURES ボタンを**全幅・角ばった矩形**で積み、選択中だけ色が変わる。全体はリベット（四隅のボルト）留めの金属パネルで区切られ、セクション見出し（STATS / EQUIPMENT 等）は太いディスプレイ書体で「刻印」されている。リソース表示は色付きの**埋め込みブロック**（緑/青/赤の面に数値）で、バーではなく“量そのもの”を見せる。アイテムは太枠スロットのグリッド。
→ 要点: 密集した管理画面でも「全部が同じ太さの枠で部品化」されていればゲームに見える。逆に**細い1〜2px線＋丸ピル＋余白**は業務アプリの記号。

### F3. デスクトップ常駐型は「アイコンレール＋隣接パネル」が合意形（Rusty's Retirement / Tiny Pasture）
プロジェクト内調査（STRIP_CANON_RESEARCH.md §a）で確認済み: Rusty's は帯の右端にアイコンレールを常駐させ、パネルはレールに隣接して開く。通貨表示はパネル側に集約。Tiny Pasture はメイン画面右側にショップパネルが常駐し、ステータスは対象クリックで見る。
→ 要点: 本作の「二窓構成（帯＋管理ウィンドウ）」自体は正本準拠。管理ウィンドウ内部でも、**タブを“左レールのアイコン＋ラベル”に寄せる**のがジャンルの文法（後述 P2。ただし第一弾は上タブのまま見た目だけ寄せる）。

### F4. ピクセルUIキットの共通文法（itch.io の UI キット群を横断確認）
Gridwright Idle & Incremental UI（放置/クリッカー専用キット）、Horror UI Kit、各社 9-slice パックの構成がほぼ一致する:
- **9-slice パネル**（角を壊さず伸縮する枠）が全キットの基盤部品。
- 部品の基本セット: パネル／ボタン（**normal・hover・pressed の3ステートを別絵で持つ**）／タブ／スロット（アイコン受け）／バー／通貨ピル／スクロールバー／チェックボックス・トグル。
- 放置ゲーム専用キットでは「通貨ピル」「買う ×1/×10/MAX トグル」「スロット付きアップグレード行」が標準部品として売られている＝**ジャンルの玩家が期待する部品の顔**が決まっている。
→ 要点: CSS でもこの部品文法（枠の太さ・3ステート・スロット・ピルの顔）は再現できる。絵としての 9-slice 化は最終段階でよい（P2）。

### F5. Melvor Idle は「反面教師」として有効
Melvor は三分割レイアウト（左メニュー／上バー／メイン）自体は本作と同型だが、レビューで繰り返し「interface is awful」「ボタンの文字コントラストが読めない」「買い物が3クリック」と叩かれている（Steam レビュー実読）。
→ 要点: 構造ではなく**コントラストとクリック数と部品の顔**が評価を分ける。本作は現行でも1クリック購入ができているので、見た目の部品化に集中すればよい。文字色と背景のコントラスト比は必ず確保する（後述トークンで担保）。

### F6. 「ゲームらしさ」のチェックリスト（Game UI Design Workbook の引渡し基準より）
- 全操作に強さの合った即時フィードバック（押下の沈み込み、カウンタの動き）。
- HUD・メニュー・一覧で**タイプ（書体/色/形/アイコン）の様式が統一**されている。
- インタラクティブ要素は**全ステート（通常/ホバー/押下/無効）が定義済み**で実寸テスト済み。
- パネル類は 9-slice の伸縮ラインが定義されている。
→ 本仕様の領域別仕様はこの4点を全領域で満たすことを合格条件とする。

### F7. Rusty's の色づかい
Rusty's は Stardew の色彩感覚を参照したと開発者が公言し、全体は「soothing earth tones（落ち着いた土色）」で統一される。本作は既に土色＋クリームのパレット（スプライト palette の `#FFF5E6 / #DFCDB7 / #C99A66 / #996D49 / #604B40`、帯の机 `#b08954 / #cfa06a`）を持っている。**新しい色を持ち込まず、ゲーム内素材の色をUIに昇格させる**のが統一感の近道。

## 2. 現行診断 — 何が「HTML を引きずっている」のか

現行 `<style>` の実読からの診断:

| 現行 | 問題 | 対応先 |
|---|---|---|
| `button{border-radius:999px}` ピル型 | ピルは Web/モバイルUIの記号。ゲームのボタンは矩形の板 | §4.5 板ボタン化 |
| 全要素が `2px solid var(--line)` の細枠・影なし | 厚みゼロ＝紙。Stardew/NGU は太枠＋沈み込み | §3 枠トークン |
| `:hover` は枠色が変わるだけ、`:active` 未定義 | 押した手応えがない（F6違反） | §4.5 3ステート |
| `.tabs button.on` が「濃色ピルに反転」 | フォルダタブでもレールでもなく Web のセグメント切替の顔 | §4.3 |
| `.kv` / `.log` の `border-bottom: dashed` | 破線は帳票・Web の区切り。ゲームは溝（groove）か面の段差で区切る | §4.6 |
| `.panel{max-height:640px;overflow:auto}` の素スクロール | OS デフォルトのスクロールバーが一番「ブラウザ」を暴露する | §4.8 |
| `select` / `textarea` がほぼ素 | フォーム部品の素顔＝HTML感の震源 | §4.9 |
| 数値に等幅指定なし | カウントアップ時に桁が揺れて安く見える | §3.4 tabular-nums |
| 絵文字アイコンが裸で並ぶ | アイコンはスロット（受け皿）に入って初めて部品になる（F4） | §4.6 アイコンソケット |
| 色トークンが UI 専用に分離（`--accent:#e8873a` 等） | ゲーム素材（スプライト/帯）と色味が微妙に別系統 | §3.1 素材色へ寄せる |

## 3. ビジュアル言語トークン

すべて既存パレット（スプライト palette 定義＋帯の家具色＋現行 CSS 変数）からの昇格。新色の発明はしない。

### 3.1 色
```css
:root{
  /* 紙と素材 */
  --paper:#fff5e6;        /* W: パネル内面・カード面（みゅけの白） */
  --paper-2:#f9ecd4;      /* 内面の沈んだ面・行の縞 */
  --cream:#f6efe6;        /* 現行 --bg: ウィンドウ地 */
  --tan:#dfcdb7;          /* w: タブ未選択・溝の色 */
  --wood:#c99a66;         /* T: ヘッダ帯・見出しプレート */
  --wood-d:#996d49;       /* t: 木の影色・スクロールバー */
  --desk:#b08954;         /* 帯の机と同色: 最も濃い木部 */
  /* インクと枠 */
  --ink:#463126;          /* F: 文字・枠の主色（現行 #4a3b2c を素材寄りに微調整） */
  --ink-soft:#604b40;     /* O: 副枠・スロット枠 */
  --sub:#8a755c;          /* 現行どおり: 補助文字 */
  /* アクセント（素材色） */
  --accent:#f49a45;       /* A: プライマリボタン・強調 */
  --accent-d:#cc6c32;     /* a: プライマリのベベル影 */
  --green:#85ca91;        /* G: 良い状態・購入可能 */
  --green-d:#437660;      /* g */
  --gold:#f8cf69;         /* h: 実績・レア・プレステージ */
  --gold-d:#f1bf41;       /* Z */
  --red:#c53333;          /* H: 首輪の赤。危険・閉じる・ボトルネック */
  --blue:#71bed3;         /* B: 情報・アップデート（現行 #update-card の場当たり青を置換） */
}
```
コントラスト: 主要文字は `--ink` on `--paper`（十分濃い）。白文字は `--accent-d` 以上の濃さの面上でのみ使う（現行 primary の `#e8873a` 上の白は F5 の轍。primary は濃色文字 or 影付き白文字にする: §4.5）。

### 3.2 枠・影・角（「板」の物理）
- **枠**: 主枠 `3px solid var(--ink)`、副枠 `2px solid var(--ink-soft)`。1px 線は原則禁止。
- **硬い影**（ぼかし影は Web の記号なので原則禁止）:
  - パネル: `box-shadow: 0 4px 0 rgba(70,49,38,.28)` ＋ 内側ハイライト `inset 0 2px 0 #ffffff90`。
  - ボタン: 下ベベル `inset 0 -5px 0 rgba(0,0,0,.16), inset 0 2px 0 rgba(255,255,255,.4)`。
  - スロット/溝: `inset 0 2px 0 rgba(70,49,38,.18), inset 0 -1px 0 #fff`（彫り込み表現）。
- **角**: パネル 12px、カード 10px、ボタン 8px、チップ 999px は**通貨チップ専用**に限定（F4 の「通貨ピル」はジャンルの正式部品なので残す。それ以外からピルを排除）。

### 3.3 部品の3ステート（全インタラクティブ要素に必須）
- hover: ベベルを保ったまま面を 1 段明るく＋枠を `--ink` に。
- active（押下）: `transform: translateY(3px)` で**物理的に沈み**、下ベベルを `-2px` に潰す。音がなくても「押した」が伝わる最小のジュース（POLISH_RESEARCH のジュース論と接続）。
- disabled: 彩度を落とし（`filter:saturate(.4)`）、ベベルなし、影なし。「買えない」は opacity 一律ではなく“乾いた板”にする。

### 3.4 書体（オフライン前提）
- 追加フォントは初期段階では入れない。システムスタックに Windows 実機向けを明示: `"Hiragino Maru Gothic ProN","Yu Gothic UI","Meiryo UI","Noto Sans JP",sans-serif`。
- 見出し: `font-weight:800; letter-spacing:.03em`。タイトルは 20px 800。
- **数値は全て `font-variant-numeric: tabular-nums`**（リソースチップ・価格・統計）。カウントアップ時の桁揺れを消す。
- オプション（P2）: 見出しと数字だけに OFL の日本語ピクセルフォント（PixelMplus 等）をサブセット同梱し「刻印」感を上げる。容量と Tauri 同梱手順の確認が前提で、必須ではない。

## 4. 領域別仕様

### 4.1 ウィンドウ地とヘッダ
- 地（body）: `--cream` に、ごく薄い `--tan` のドット格子（`background-image: radial-gradient(...)` の 2px ドット、帯canvas と無関係な CSS のみ）を敷き「紙の上」から「作業机の上」へ。やり過ぎ注意（コントラストを落とさない濃さで）。
- ヘッダ: 現行の「白バー＋下線」を**木の帯**に変える: 背景 `--wood`→`--desk` の2段（面＋下ベベル影）、下端は `3px solid var(--ink)`。タイトルは木に刻まれたプレート風: 白抜きではなく `--ink` 800 ＋ `text-shadow: 0 1px 0 #ffffff55`（彫刻のハイライト）。
- 「デスクトップに戻す」は通常ボタン列から独立させ、ヘッダ右端の**赤い×系の“閉じる板”**（Stardew の赤×ボタン文法。色は首輪赤 `--red`）として置く。帯側の「ひらく」と対になる物理ボタンだと分かる顔にする。

### 4.2 リソースチップ（🪙コイン等）
- F4 の「通貨ピル」として正式化: 面 `--paper`、枠 `2.5px solid var(--ink)`、**内側に彫り込み**（§3.2 の溝影）、アイコンは 18px のソケット円（`--tan` 地）に入れる。数値は tabular-nums 800。
- 増減時に既存のカウントアップ（Sprint 2）と合わせ、チップが一瞬だけ `--gold` に光るクラス（`.bump`）を用意（CSS のみ）。
- 「あと○○で買える」系の含み表示（`.res small`）はチップ内に残すが、色は `--accent-d` に統一。

### 4.3 タブ（9タブ）
- **フォルダタブ**化: タブ列はパネルに“くっついて”いること。未選択タブは `--tan` の板で `translateY(4px)` 沈み、選択中タブは `--paper` の板でパネルと同色・下枠を消して**パネルと一体化**（`border-bottom: 3px solid var(--paper)` で接続）。角は上だけ 8px。
- 各タブ: アイコン（絵文字）は 20px ソケット（§4.6）に入れ、ラベル 800。ピル形状と「濃色反転（現行 .on）」は廃止。
- バッジ: 買えるものがあるタブ／新しい依頼には右上に `--red` のドット（＋任意で数字）。POLISH_RESEARCH の段階的開示（ロックタブ）とも両立: ロック中タブは乾いた板＋🔒、解放時に光る。
- 横幅が足りない場合の折返しは現行どおり flex-wrap でよい（2段になってもフォルダの顔は保てる）。

### 4.4 パネルとセクション見出し
- `.panel`: 面 `--paper`、主枠 3px、硬い影、内側にもう一段 `--paper-2` のインナー面（padding で見せる二重構造＝F1 の2階層）。`border-radius:12px`。
- セクション見出し（現行 `.panel h3`）: **リボンプレート**化。左に `--wood` の小プレート（アイコンソケット付き）が本文面から少しはみ出す形、`--ink` 800、下に溝線（`border-bottom: 2px solid var(--tan)` ＋ `box-shadow: 0 1px 0 #fff`）。h3 の素テキスト感を消す。
- パネル内の小見出し・注記（`.note`）は現行の格を維持するが、色は `--sub` に統一（場当たり色の排除）。

### 4.5 ボタン
- 共通: 矩形（radius 8px）、`2.5px solid var(--ink)`、§3.2 のベベル、§3.3 の3ステート、13px 800。**999px ピルを全廃**（通貨チップと `#bn-chip` の警告ピルのみ例外として残すかは §4.10）。
- `.primary`（購入・決定）: 面 `--accent`、ベベル影は `--accent-d`、文字は `--ink`（濃色）＋薄い白ハイライト。現行「オレンジ地に白文字」よりコントラストと素材感が両立する。
- 二次ボタン: 面 `--paper`、ベベルは `--tan`。
- 危険/破壊的（セーブ削除等）: 面は紙のまま、枠と文字を `--red`。赤ベタは「閉じる板」（§4.1）だけ。
- 購入ボタン（`.buybtn`）: 価格は右端に**価格タグ**（`--gold` の小プレート、枠付き）として分離表示。「あと○○」ヒント（`.ahint`）と買える瞬間のパルス（既存 `affordPulse`）はベベルと競合しないよう、パルスは外側の硬い影の色変化で表現し直す（既存 keyframes の流用可、色だけ `--gold-d` に）。

### 4.6 リスト・行・カード（`.item` / `.buy` / `.kv` / スタッフ行）
- `.item`: 「白いカード」から「スロット付きの行板」へ: 面 `--paper`、枠 2.5px、左に **44px のアイコンソケット**（`--paper-2` の彫り込み面＋枠。絵文字 or スプライトが入る受け皿）。名前 800、説明 `--sub` 12px は現行踏襲。
- 行の区切りは破線を全廃し、**面の段差**で分ける: 偶数行 `--paper-2` の縞 or 行間 6px の溝。`.kv`（統計）も破線をやめ、溝線（§4.4 の2px tan＋白ハイライト）に。
- スタッフ行: 毛色ドット（既存 `.coatdot`）をソケット内の色チップとして格上げし、Lv は金プレートの小バッジ、訓練ボタンは二次ボタン。雇用済み/未雇用は面の乾き具合（§3.3 disabled 文法）で区別。
- ホバー: 行全体が `translateY(-1px)`＋影が一段濃くなる（クリックできる行だけ）。

### 4.7 メーター・バー（`.meter` / `.lampbar` / 集中力・進捗）
- トラック: 彫り込み（溝影）＋枠 2px `--ink-soft`、radius 6px。高さ 12px に厚くする。
- フィル: 素材色のベタ＋**斜めストライプ**（`repeating-linear-gradient(45deg, transparent 0 6px, rgba(255,255,255,.18) 6px 12px)`）＋上面ハイライト線。ゲームのゲージは「色水」ではなく「柄のある素材」で読ませるのが定番（F4 のバー部品）。
- 集中力（`.meter.conc`）は `--accent` 系、進捗は `--green` 系で現行の意味を維持。ボトルネック時は工場図の該当バーだけ `--red` ストライプに（信号機図 `.lampdiagram` と連動、現行構造のまま色だけ差す）。
- 任意（P1）: 25% ごとの刻み線を `background-size` の目盛りで重ねる。

### 4.8 スクロールバー
- `.panel` と `.log` に webkit スクロールバーを定義: 幅 12px、トラック `--tan`（溝影つき）、つまみ `--wood-d`＋`2px solid var(--ink)`＋radius 6px、hover で `--desk`。Tauri（WebView2 / WebKit）でも `::-webkit-scrollbar` が効く前提で、効かない環境では素のまま（劣化しても壊れない）。
- Firefox 向け `scrollbar-color` も併記（2行で済む）。

### 4.9 フォーム部品（設定タブの select / textarea / チェック類）
- `select`: 紙面＋主枠＋ベベルを持たせ、ボタンと同じ板の顔に（OS 素の矢印は残っても枠で部品化する）。
- `textarea`（自由タイピング欄等）: 罫線ノート風: `--paper` に `background-image: repeating-linear-gradient(transparent 0 25px, var(--tan) 25px 26px)` の行罫＋溝影。「入力欄」ではなく「ノートに書く」顔にする。
- チェックボックス/トグル（入力カウント ON/OFF、音量等）: P1 で**板スイッチ**に置換（label＋隠し checkbox＋板のノブ）。純 CSS で実装可能、JS の状態管理は現行のまま。

### 4.10 通知カード・チップ類（`#return-card` / `#update-card` / `#bn-chip` / トースト相当）
- 3種を「プレート」様式に統一: 主枠＋硬い影＋左端に太い色帯（帯の幅 6px、色帯＝意味色）＋見出し 800。現行の `#update-card` の場当たり青（`#5b8dd9`）は `--blue` に置換、`#return-card` の橙枠は `--gold-d` の色帯に読み替え。
- `#bn-chip`（ボトルネック警告）: ピル維持でも可だが、色帯プレートの小型版に揃えると全体が締まる。帯側チップと顔を揃える（帯 HUD の `.hud-chip` と同じ枠・影トークンを共有するのが理想。帯 canvas 側は別実装なので、まず管理画面側だけでもトークンを一致させる）。

### 4.11 実績スタンプ（`.stamp`）
- 「スタンプ」の名に寄せる: 二重枠（外 2.5px／内 1px の `outline` 併用）、取得済みは `--gold` 地＋わずかに回転（`transform: rotate(-2deg)`、並び順で交互）、未取得は乾いた板＋グレースケール気味。現行の色替えだけより“押された判子”になる。回転はレイアウトを崩さない範囲（±2deg）。

## 5. 実装計画（視覚的リターン／労力 順）

### P0 — 純 CSS のみ（`<style>` の書き換え中心、DOM・JS 無変更）★最優先
1. トークン差し替え（§3.1）と枠・影・角の適用: `.panel` / `header` / `.item`。
2. ボタン全面刷新（§4.5）: ピル全廃、ベベル＋押下沈み込み、primary の文字色是正。
3. タブのフォルダ化（§4.3）: `.tabs button` と `.on` の再定義のみで可（接続処理含む）。
4. リソースチップの彫り込み化＋ `tabular-nums` 全体適用（§4.2, §3.4）。
5. スクロールバー定義（§4.8）。
6. メーターのストライプ＋溝化（§4.7）、破線の溝線化（`.kv` / `.log`）。
完了条件: 全タブのスクショで「Web フォームに見える要素」が消えていること。スモークテストは DOM 構造に触れないので無影響のはず（クラス名・ID は一切変えない）。

### P1 — CSS ＋ 軽い DOM/クラス追加（renderPanel 側の小変更を伴う）
7. セクション見出しのリボンプレート化（§4.4）: h3 への span 追加 or `::before` ソケットで吸収できる範囲は CSS のみ。
8. 行のアイコンソケット（§4.6）: `.item` 生成側に `.sock` 要素を追加。スタッフ行の Lv バッジ、価格タグ（§4.5）もここ。
9. 通知プレート統一（§4.10）、スタンプの判子化（§4.11）。
10. 設定タブの板スイッチ、`select`/`textarea` の部品化（§4.9）。
11. ヘッダ木帯＋「デスクトップに戻す」の閉じる板化（§4.1）: ボタンの配置クラス追加のみ。
12. タブバッジ（買える/新着ドット、§4.3）: 判定ロジックは既存の afford 判定を流用。

### P2 — 構造変更（効果は大きいが要検討・別途合意）
13. 左アイコンレール型ナビへの移行（F3 のジャンル文法。ウィンドウ幅と `main` レイアウト変更を伴う。やるなら P0/P1 の様式をそのまま流用できる設計にしておく）。
14. 枠の本物の 9-slice 化: CSS の `border-image` に小さな枠 PNG（四隅＋辺）を当てる。絵は帯の家具と同じ木目で新規に描く（sakuri 画 or 生成）。P0 の CSS 枠と差し替え可能な形にしておく。
15. 見出し・数字専用ピクセルフォントのサブセット同梱（§3.4 オプション）。
16. タブ切替時の小さな遷移（パネルの 60ms フェード/スライド）。帯の「邪魔しない」原則に反しない範囲で、開く瞬間のみ。

## 6. アンチゴール（やらないこと）

- **フレームワーク・UI ライブラリ・Web フォントの CDN 読込は禁止**（オフライン出荷、単一 HTML、軽量の正本に反する）。
- マテリアル風のぼかし影・グラデーション多用・ガラス質感は使わない（硬い影とベタ面がこのゲームの素材感）。
- ピル（999px）の全面使用、破線区切り、OS 素のフォーム部品・スクロールバーを残さない（通貨ピルのみ F4 の正式部品として例外）。
- 管理画面にシーン/イラスト面を描かない（R11）。装飾は「板・枠・小物プレート」の範囲まで。
- DOM の ID・クラス名・構造を P0 では変えない（スモークテストとセーブ互換を壊さない）。色の場当たり追加をしない（必ず §3.1 のトークンから）。
- 帯（ストリップ）側の見た目変更は本仕様の範囲外。帯 HUD チップとのトークン共有は「揃えられたら良い」任意項目に留める。
- アニメーションは押下・切替の最小限。常時動く装飾は入れない（常駐アプリの「邪魔しない」原則）。

## 7. 検証

- 9タブ全ての before/after スクショ（管理ウィンドウ単体）を取り、§2 の診断表が全項目解消しているか目視で対照する。
- F6 チェック: 全ボタンに hover/押下/無効の3ステートが効くこと、特に「買えない購入ボタン」「ロック中タブ」「押下中の主要ボタン」を撮る。
- 既存スモーク全件パス（P0 は無変更のはず）＋バランス sim 不変。実機（Windows）でフォントスタックとスクロールバーの効きを確認（VM の Linux 描画と実機で見えが違う部分: 書体・スクロールバー）。
