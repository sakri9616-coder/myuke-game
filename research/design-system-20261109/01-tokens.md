# 01 トークン： 現行の棚卸しと、経営レイヤーの追加提案

Astryx の方式は「テーマ＝CSS カスタムプロパティの上書き集」。みゅけのパネルは実はすでにこの形になっている（`game/src/styles.css` の `body:not(.strip)` スコープで `--ide-*` を定義し、旧トークンを読み替えている）。足りないのは、**間隔・文字・経営数値のトークン化**と、**棚卸しの文書化**。ここでは実測を正とし、追加分は「提案（未実装）」と明記する。

### 書体

- `--mono`: "Miyuke Editor Latin"（Latin は等幅、unicode-range で日本語は `--jp` の丸ゴ系にフォールバック）。**数値は等幅で桁が揃う**のが既存の強み。
- パネル内の角丸は `border-radius: 3px` が圧倒的多数（実測 14 件）＝「四角く堅い」が実装でも正本になっている。

## 2. 欠けているもの（実測で確認した穴）

1. **間隔にトークンがない。** padding/gap は px 生値が散在し、画面ごとに微妙に違う余白が生まれる余地がある。Astryx の tokens 参照（spacing / color / radius を CLI で引ける形）と同じく、梯子を決めて名前で引く形にしたい。
2. **文字サイズにトークンがない。** 実測の頻出は 12.5px（本文）、11–11.5px（注記）、13.5px（見出し）。KPI 級の大数字の規定がない。
3. **「増減」を表す専用トークン／部品がない。** `.ratecell` の `--pipe-tone`（正常＝緑／黄／赤）が部分的に担っているだけ。経営画面の主役である「前回比・目標比」の表現がアドホック。
4. **表のトークンがない。** 行高・階層インデント・合計行の扱いが画面ごと。組織（本社→部署→子会社）の階層表を書くときに毎回発明することになる。

## 3. 追加提案（未実装。実装時はこの表が仕様）

### 間隔の梯子（現行の頻出値から逆算）

```css
--sp-1:4px;  /* 行内・チップ内 */
--sp-2:6px;  /* カード内の詰め */
--sp-3:8px;  /* 標準の gap */
--sp-4:10px; /* セクション内 */
--sp-5:14px; /* セクション間・画面端 */
```

### 文字の梯子

```css
--fs-cap:11px;   /* 注記・凡例 */
--fs-body:12.5px;/* 本文（現行頻出） */
--fs-head:13.5px;/* 見出し（現行） */
--fs-num:13px;   /* 表の数値 */
--fs-kpi:20px;   /* 経営サマリの主数字（新設） */
```

### 経営レイヤー（新設）

```css
--delta-up:var(--syn-green);   /* 増・好転 */
--delta-down:var(--ide-errtx); /* 減・悪化 */
--delta-flat:var(--ide-sub);   /* 横ばい */
--kpi-ink:var(--syn-num);      /* KPI の数字色 */
--row-h:26px;                  /* 表の標準行高 */
--row-line:var(--ide-linesoft);/* 表の罫 */
--indent:14px;                 /* 階層表の1段インデント */
--total-bg:var(--ide-panel2);  /* 合計行の面 */
```

狙い： 経営の数字は「色は既存の意味色から借り、大きさと対照で格を出す」。新しい色は1色も増やしていない（上の新設はすべて既存トークンへの別名＋寸法のみ）のが要点。

## 4. 運用

- 新しい色を足したくなったら、まず §1 の意味色表に当てはまる役割がないか探す。当てはまらない場合だけ、この文書の表に行を足してから使う（規約書 `02` §2 と連動）。
- 帯側の暖色トークン（`--paper`/`--wood` 等の素の定義）は別系統。パネル側スコープの読み替えを正とし、帯の定義をパネル都合で書き換えない。
