# 03 経営パターン： Astryx テンプレートから「洗練された会社経営の文脈」を写す

sakuri の狙い（2026-11-09）： 「会社経営だから洗練されたデザインの文脈は欲しい」。Astryx のテンプレート集は、Meta の 13,000+ アプリで鍛えた「画面の型」のカタログである。ここではその中から経営シムに効く型だけを抜き、みゅけのパネル各所へ写像する。写すのは**情報の組み立て方（文脈）**であって、見た目の皮ではない。皮は `01`/`02` の正本（VS Code 中立色・密度・四角さ・可愛いコピー）が担う。

## 数字の憲法（Data Dashboard の原則）

Astryx の Data Dashboard の一文が経営画面の核心：

> 「Every number is shown against another number.（すべての数字は、別の数字と対にして示される）」——タイルには小さな推移線（スパークライン）と期間比較の増減が必ず付く。

みゅけへの翻訳（パネル全体の憲法として採用を提案）:

1. 資金・DP/分・星屑のような主数字は、**前回開いた時との差／次の目標までの残り／全体に占める割合**のどれかを必ず添える。
2. 増減の色は `--delta-up/down/flat`（`01` §3）の3値だけ。好悪の判定が要る数字（詰まり率等）は既存の診断文法（緑／黄／赤）に寄せる。
3. 推移を見せたい数字には、棒でも点列でもいいので**小さな形**を添える（スプラークライン相当）。帯のプロジェクトボードが担う「一目で進捗」と同じ文法を、パネルの数字にも。

## 写像表

### A. 経営サマリ（会社タブの頭）← Executive Summary Dashboard ＋ Analytics Dashboard

- Astryx の型： 見出し数字のスコアカード（期間増減＋状態色つき）→ 目標達成バー → 推移のグリッド → 書面コメント欄、という「報告書の形」。Analytics 版は見出しタイル→図→表の三段で、全体を1本のフィルタバーが貫く。
- みゅけ写像： 会社タブの最上段を「経営サマリ」として型で固定する。スコアカード＝社格／資金／DP毎分／総勢の4枚（各々に数字の憲法を適用）。目標達成バー＝次の社格・次ティアまでの進捗。推移＝星屑・資産の小さな推移。コメント欄＝**秘書の所感**（ゲーム側の短い一言。フラバーの延長で、報告書の「所見」欄の可愛い翻訳）。
- 効きどころ： 経営期（準大手〜）で「会社を経営している」感触を作るのは帯ではなくこの報告書の形。社格が上がるほどサマリが育つ（カードが増える／推移が出る）設計と相性がいい。

### B. グループ経営（持株化後）← Portfolio Dashboard

- Astryx の型： 保有価値と変動のタイル → 構成の積み上げ推移 → 寄与の大きい順のランキング表。
- みゅけ写像： 持株化後のグループビュー。総資産の推移、構成（本社ライン／子会社群／棚の割合）、子会社の寄与ランキング表（配当順）。部分 EXIT の判断材料はこの画面に集約する。
- 効きどころ： 終盤の判断（育てる／売る）を「勘」から「数字の対照」に変える。EXIT が経営の到達点である以上、その判断画面の格がゲームの格になる。

### C. 組織表（部署・子会社・スタッフ）← Tree Table ＋ Grouped Table

- Astryx の型： Tree Table は「親行が子からロールアップされる階層表」。Grouped Table は「畳めるセクション＋件数」で長い一覧を数ブロックに読ませる。
- みゅけ写像： 本社→部署→スタッフ、持株→子会社、の階層を**1枚の階層表**で見る型。親行には子の合計（人員・DP/分・配当）をロールアップ表示。子会社列（現行 `.subcols` の横カード列）は「現在の主役表示」として残し、経営が深まったらこの表ビューを併設する。
- 効きどころ： 総勢100人超スケールの設計（子会社＝抽象人員数で伸ばす）に対して、カード列だけでは一覧性が死ぬ。階層表が「大きな会社」の視覚文脈そのものになる。

### D. プロジェクト／案件 ← Project Status Dashboard ＋ Work Item Detail

- Astryx の型： 進捗ドーナツ、「今日」マーカーつきの時間軸バー、担当者ごとの表、詰まり（at-risk）リスト、バーンダウン。詳細形は「状態セレクタ＋子タスクのチェックリスト＋プロパティ欄＋履歴フィード」の2カラム。
- みゅけ写像： 工場タブの案件表示に、詰まりリスト（バグ・負債・詰まり案件を状態色で集約）を型として追加する余地。依頼詳細は Work Item Detail の形（状態／担当／残作業／履歴）で揃える。
- 注意： 帯のプロジェクトボード（リーダーボード白板）が進捗の正本表示。パネル側は「管理のための詳細」に徹し、同じ情報を二重に主役にしない。

### E. 判断フロー（設立・EXIT・持株化）← Dialog Wizard

- Astryx の型： 2〜4ステップの短いフローをダイアログで進め、下の画面の文脈を失わない。ステップ標識は小さく、操作行は固定。
- みゅけ写像： 子会社設立（ジャンル→方針→確認）、EXIT／持株化（見込み→引き継ぎ特典→最終確認）を、1ボタン＋確認文の現在形から**段階ダイアログの型**へ寄せる下地にする。各ステップで数字は再計算され、最終確認に合計が出る（Checkout Wizard の「サマリが常に見え、答えが変わると再計算される」文法も同系）。
- 効きどころ： EXIT と持株化はゲームで最も重い判断（儀式としての格が必要、という既存決定とも一致）。フローの形がそのまま重みを演出する。

### F. 設定 ← Settings Panels

- Astryx の型： 左にセクション一覧、右のペインが切り替わり、行はその場で編集（別フォームを開かない）。
- みゅけ写像： 現行の設定系（配置・音・表示サイズ等）は項目が増えている。「左ナビ＋右ペイン＋行内編集」の型に揃えると、項目追加のたびに迷子にならない。

### G. 画面の骨格 ← IDE テンプレート（裏付けとして）

- Astryx の IDE 型は「リサイズ／折りたたみ可能な多ペインの密なワークスペース」。みゅけのパネルは分割ビュー（タブをドラッグして列を割る）を持ち、既にこの文法の内側にいる。**大規模プロダクトのデザインシステムが同じ形を「型」として正典化している**ことは、現行パネルの方向が我流ではない裏付けになる。新規の骨格は発明せず、この型の中で部品を増やす。

## 優先度（実装するなら、の順）

1. **数字の憲法＋経営サマリ（A）** — 全画面の数字の出し方が揃うと、それだけで「経営の道具」に見える。コストも小さい。
2. **判断フローの型（E）** — EXIT／持株化の格に直結。既存決定（持株化は最も重い儀式）とも一致。
3. **組織の階層表（C）** — 経営期の規模感の受け皿。中盤以降の改修と同時に。
4. **グループ経営（B）** — 持株化まわりの改修とセットで。
5. **詰まりリスト（D）／設定の型（F）** — 余力で。

いずれも「タブ改修のついでに型を当てる」進め方を前提とし、この文書単独の大改修は提案しない。
