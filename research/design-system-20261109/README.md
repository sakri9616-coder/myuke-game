## 結論

- **Astryx 本体は導入しない。** React 19 + StyleX 前提のコンポーネント集であり、みゅけのフロントは React なしの素の TypeScript＋単一ファイルビルド、帯はキャンバス描画。本体導入は土台工事になり、帯には効かない。
- **取り込むのは3層の「作法と文脈」**（このフォルダの3文書）:
  1. `01-tokens.md` — テーマ＝CSS 変数トークン集という整理。現行パネルのトークンを棚卸しし、不足分（間隔・文字・経営数値まわり）を提案する。
  2. `02-panel-conventions.md` — パネル UI の規約書。Astryx の旨みは「規約が全部文書化されていて、人も AI も同じ形に書ける」ことにある。開発主力がクラウド Claude セッションのみゅけにこそ効く。
  3. `03-management-patterns.md` — **本命。** Astryx のテンプレート（画面パターン）カタログから、会社経営シムの管理画面に写せる「洗練された経営 UI の文脈」を抜き出し、みゅけの各タブへ写像したもの。
- 本フォルダは**設計参照資料**であり、コード変更は含まない。実装は各タブ改修のタイミングで、この文書を根拠に進める。

## 前提（変えてはいけない正本）

- 色の正本は sakuri の VS Code 画面： 面は中立色（#1E1E1E/#252526/#2D2D2D、線 #454545、文字 #D4D4D4、ステータス青 #007ACC）。**ただし意味色（`--syn-*` 群）まで VS Code 化しない**（sakuri 訂正 2026-10-26）——意味色は既存のシンタックス／診断色の文法が正本。
- 主レバーは色ではなく**密度と堅さ**： 詰めた padding/gap、1px の線、四角いチップ、最小限の影。文言とフォントの可愛さは残す（エンジニア風シック）。
- 帯（body.strip）は無関係。パネルの話はすべて `body:not(.strip)` スコープで完結させる。猫の絵・吹き出し・ポートレート受けはクリーム #FFF5E6 の「写真の差し込み」として温存（現行 CSS の設計判断）。
- メニュー閉＝中立状態の原則は不変。パターンはパネル内経営の表現力を上げるためのもので、帯で完結すべき体験をパネルへ移す口実にしない。
