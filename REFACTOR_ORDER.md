## Mission

1. AUDIT first: map the structure, coupling hotspots, and hunt for defects
   (crashes, dead code, duplicated logic, save/load risks, inconsistent
   state handling, tick/render performance hazards, unreachable branches).
   The user expects hidden flaws to surface — evidence-backed findings are
   a primary deliverable, not a by-product.
2. Then REFACTOR in small stages, in descending safety order (dead-code
   removal with proof, pure-function extraction, deduplication, boundary
   cleanup), committing and pushing each stage separately on this branch.

## Hard constraints

- Refactor commits are STRICTLY behavior-preserving: no gameplay or
  balance numeric changes, no visible behavior changes.
- Save format and load semantics unchanged: SAVE_KEY stays
  "miyuke-save-v1"; do not change what a save contains or how old saves
  load.
- Never touch the generated sprite block (lines 970–11,677) or any art
  data. No new art of any kind.
- No version bump, no release, no tags, no merge to main. Commits and
  pushes stay on `refactor/opus-20261027`.
- Defect fixes: only clear, unambiguous bugs, each in its own commit
  labeled "fix:", kept separate from "refactor:" commits. Anything that
  needs a design or balance decision goes to FINDINGS — do not change it.

## Verification gate (mandatory after EVERY stage)

Run exactly this one command from the repository root:

  node refactor-gate.cjs

It runs the smoke test and balance sim against this checkout (the rig
otherwise defaults to an absolute path that does not exist here; the gate
script sets the override internally) and prints GATE: PASS or GATE: FAIL.
Baseline at this branch's base commit: smoke 801 passed / 0 failed; sim
ratios dust 2.45 / coin 1.90 / count 1.31 (gates: dust ≥1.3, coin ≥1.1,
count ≥1.0, first release ≤5 min for both profiles).

If a stage breaks the gate and you cannot fix it in 2 attempts, revert
that stage, record what happened in the report, and continue with the
next stage. Never leave the tree red.

## Deliverable

REFACTOR_REPORT.md in the repository root, committed and kept updated:
- Structure map and coupling hotspots.
- FINDINGS: every defect found, with severity, file/line evidence, and
  whether fixed (commit hash) or left for a human decision (and why).
- Per-stage log: what changed, gate results before/after.
- Anything you deliberately left alone, and why.

When you finish or run out of safe stages, end with the report complete
and the tree green.
