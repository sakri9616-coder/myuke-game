# 帯スクショのベースライン

`tools/strip-capture.js` で撮った帯の「前回正常だった姿」を置く場所。
`tools/verify-all.sh` は毎回、現行ショットとここを `tools/strip-diff.py` で比べ、
閾値を超えた変化だけを WARNING（目視せよ）として出す。**差分は FAIL にはしない**。
帯はアニメーションするため、同一条件の再撮影でも 0% にはならない。

## ファイル

- `fresh.png` — 新規セーブの帯（1280×210、撮影後 3 秒待ち）。verify-all の SHOT と比較。
- `veteran.png` — `tools/strip-seeds/veteran.json` を投入した進行後セーブの帯
  （スタッフ3匹・第2ライン机・研究机・棚の作品・50%ボード・5000コイン）。
  verify-all の SHOT-SEED と比較。

## 実測ノイズ（2026-10-26、同一条件の再撮影2回）

| 比較 | 変化率 | 主因 |
|---|---|---|
| fresh vs fresh | 1.43% | コーディングアニメのフレーム・吹き出しの有無 |
| veteran vs veteran | 5.68%・8.38%（2回実測） | 上記＋スタッフの歩行位置（ランダム） |
| fresh vs veteran | 31.24% | 家具・スタッフ・ボード進捗の違い（＝意図した差） |

## 閾値（verify-all.sh に固定）

- fresh：5%（ノイズ 1.43% の約3.5倍。家具欠落・ボード消失級の変化はこれを超える）
- veteran：12%（ノイズ実測 5.68%・8.38% に対し余裕を持たせた設定。歩行ノイズで誤警告しないための緩め設定）

閾値を超えたら、差分図（`strip-diff.py --out=...`）と現行ショットを目視し、
意図した変化ならベースラインを撮り直して置き換えること。
ベースラインの置き換えは「見た目が正しいことを確認してから」行い、
置き換えた理由を dev-log に残すこと。

## メニュー側キャプチャについて

`tools/miyuke-editor2-capture.js` は before/after 2版の比較専用設計のため、
単一版を回す verify-all にはそのまま接続できない。接続には
「現行版を before=after として回す自己比較」か「前回版との比較」のどちらかの
設計判断が必要で、これは仕様判断に近いため本回は接続せず、BACKLOG の
基盤整備項目に残課題として残す。
