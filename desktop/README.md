# 『みゅけ、きょうも開発中』 デスクトップ版（Tauri v2）

ゲーム本体（`../game`、TypeScript）を Tauri v2 で常駐アプリにしたものです。
フォームファクタは『デスクトップ小動物牧場』式の「壁紙の上に直接住むペット」：**起動直後はストリップ表示**が既定で、
管理画面は同じウィンドウを大きく開いて使います（ゲームの実体・WebViewは1つだけです）。
`dist/index.html` は `game` のソースからビルドされる生成物です（リポジトリには含めません。`cd ../game && npm ci && npm run build` で作られます）。
Rust側は「常駐のための枠」・モード切替・入力集計・セーブファイルの読み書きを担当します。

- アプリ名: みゅけ、きょうも開発中 / identifier: `jp.muse.miyuke`（セーブの置き場所に直結するので不変） / version 2.3.5

## 2つのモード（フォームファクタ）

- **ストリップモード（既定・起動時）**: 枠なし・完全透明・常に手前・タスクバーに出ない帯状の窓が、画面下部（プライマリモニタの作業領域の底辺＝Windowsタスクバーの上）に張りつきます。幅は作業領域いっぱい、高さは 210 論理px固定、リサイズ不可。窓自体に枠も影もカードもなく、ペットたちは壁紙の上に直接立って見えます
  - 帯の左寄り（約30%）にデスクとPCがあり、仕事中のみゅけはそこに座ります。遊び・休憩のときは帯の床を歩き回ります
  - スタッフ猫は帯をのんびり散歩します。作品をリリースすると、一番デスクに近い1匹が荷物を運んで画面端まで行きます
  - セリフはみゅけの頭上に吹き出しで浮かび、約4秒で消えます
  - 帯をクリックすると応援クリック（コンボ・クリティカルあり）。みゅけ本人をクリックすると通常の反応をします
  - 右下の小さいチップは3つだけ: 🪙コイン残高、「ひらく」（管理画面へ）、「かくす」（ウィンドウを隠す。再表示はトレイから）
  - 位置は保存されません。起動時とモード切替時に作業領域から再計算します
  - **クリックは「見えているもの」だけが受けます**: ページ側が、みゅけ・スタッフ・アヒル・机・吹き出し・右下HUDの矩形（ヒットゾーン）を Rust 側へ送り続け、シェルの常駐ループ（約50ms間隔）がグローバルなカーソル位置と突き合わせます。ゾーンの外ではウィンドウがカーソルイベントを透過させるので、**帯の下にあるデスクトップアイコンや他アプリはそのままクリックできます**。ゾーン内（ペットや机の上）では通常どおり応援クリックやボタンが効きます。帯の何もない所は素通しになるので、帯とデスクトップ作業が干渉しません
  - 調査用に環境変数 `MIYUKE_DEBUG_HIT=1` を付けると、透過の切替（時刻・カーソル位置・ゾーン数・新しい透過状態）がアプリ設定フォルダの `miyuke-hit-debug.log` に追記されます
- **フルモード（管理画面）**: 通常の枠つきウィンドウ（既定 1180×860、最小 760×560、中央表示）で全パネルが使えます
  - **戻す**: ヘッダーの「🖥️ デスクトップに戻す」ボタン、またはトレイメニューの「デスクトップに戻す」
  - フルモード時の「常に手前に表示」はトレイメニューで切り替えます（ストリップ中は常に手前で固定）
- **モードの記憶**: フルモードの位置・サイズと、フル時の「常に手前に表示」だけが `miyuke-shell.json`（アプリ設定フォルダ内）に保存され、次回に復元されます。起動時は常にストリップから始まります
- テスト用に環境変数 `MIYUKE_START_MODE=full` を付けるとフルモードで起動します

## Rust 側が担う機能

- **自動アップデート（v2.3.5〜）**: 起動時に GitHub Releases（`sakri9616-coder/myuke-game`）へ新しいバージョンが出ていないか確認します。更新があると、帯のチップ（🆕）と管理画面のカード、設定タブの「アップデート」行でお知らせし、ボタンひとつでダウンロード→インストール→再起動まで進みます。更新ファイルは署名検証されるため、別物や壊れたファイルは入りません
  - **v2.3.5 が「最後の手動インストール」です**。これを入れておけば、v2.3.6 以降はアプリが自分で更新を取りに行くので、zip をダウンロードし直す必要はありません（ポータブル版は自己更新できないため、自動更新の対象はインストーラ版です）
  - 通信するのはアップデートの確認と取得のときだけです。セーブデータや入力の集計が送信されることはありません
  - 手動確認は設定タブの「アップデートを確認」からいつでもできます。オフライン時は静かに失敗し、遊びは止まりません

- **OS全体の入力カウント（Phase 2）**: 設定タブの「OS全体の入力カウント」を ON にすると、他のアプリを使っている間のタイピングとカーソル移動も数えて、みゅけの開発ブーストに使います（換算はページ内と同じ: 4打鍵=+1DP、1000px=+1DP、1分上限45DP）
  - **既定は OFF** です。ON にするまで、OS 全体の集計（Rust 側の `rdev` リスナー）自体が起動しません
  - 数えるのは**打鍵の回数・クリックの回数・カーソルの移動距離だけ**です。どのキーを打ったか・何を打ったかは一切記録しません。集計はメモリ内のみで、通信も一切しません。いつでも設定から OFF にできます（OFF にした瞬間から数えません）
  - ON の間は、アプリ内での打鍵・カーソル集計と二重に数えないよう自動で切り替わります。統計パネルには OS 分も合算されて表示されます
  - **Windows の制限**: 管理者として実行されているウィンドウへの入力は、Windows の仕組み（UIPI）で数えられません。通常のアプリでの入力は問題なく数えられます。管理者権限は不要です
  - 調査用に環境変数 `MIYUKE_DEBUG_INPUT=1` を付けると、集計のフラッシュ（約5秒ごとの回数・距離）がアプリ設定フォルダの `miyuke-input-debug.log` に記録されます（入力の内容は記録されません）
- **トレイ常駐**: システムトレイにアイコンが出ます。メニューは「みゅけを表示／隠す」「大きく開く（管理画面）」「デスクトップに戻す」「常に手前に表示（フル時）」「終了」。トレイアイコンの左クリックでも表示／隠すができます
- **閉じる＝隠す**: ウィンドウの×ボタンを押しても終了せず、トレイに隠れます。本当に終了するのはトレイメニューの「終了」だけです
- **単一インスタンス**: 二重に起動すると、既存のウィンドウが前面に出るだけです
- **セーブの置き場所**: アプリのデータフォルダの `miyuke-save.json` が正本です（`save_game` コマンドで一時ファイル経由の置き換え書き込み。書けるのは帯ウィンドウだけ）
  - Linux: `~/.local/share/jp.muse.miyuke/miyuke-save.json`
  - Windows: `%APPDATA%\jp.muse.miyuke\miyuke-save.json`
  - 起動時に Rust がファイルを読んで帯ウィンドウへ渡します。WebView の localStorage にも同じものを控えとして書き、起動時は新しい方を使います（ファイル化以前のセーブは localStorage から読まれ、次のセーブでファイルへ移ります）

## Windowsでのインストール

配布zip（`myuke-desktop-windows.zip`）の中身:

| ファイル | 説明 |
|---|---|
| `myuke-setup-2.3.5-x64.exe` | インストーラ（NSIS）。これを実行するのがおすすめ（自動アップデートの対象はこちら） |
| `portable/myuke.exe` | インストール不要の単体版。そのまま実行できます（自己更新はしません） |
| `README.md` | このファイル |

- インストーラは WebView2 ランタイムが無い環境では、インストール時に自動で取得します（Windows 11 には通常入っています）。ポータブル版を WebView2 の無い環境で使う場合は、先に Microsoft の WebView2 ランタイムを入れてください
- **SmartScreen の警告について**: このバイナリはコード署名をしていないため、初回実行時に「Windows によって PC が保護されました」と表示されることがあります。その場合は **「詳細情報」→「実行」** を選ぶと起動できます
- アンインストールは「設定 → アプリ」から通常通りできます（ポータブル版はファイルを消すだけ）

## ビルド方法

通常の再ビルドは `bash resync-rebuild.sh` 一発です（`game` の型チェックとビルド→ Windows ビルド → 配布 zip `myuke-desktop-windows.zip` の再作成まで。納品物は Windows のみのため、既定では Linux deb をビルドしません。Linux deb も要る場合は `BUILD_LINUX=1 bash resync-rebuild.sh` または `bash resync-rebuild.sh --with-linux`）。ビルド前にリリースノート・署名鍵・版数一致を入口チェックし、不備があれば開始前に止まります。v2.3.5 からはスクリプトが Updater 用の署名も行い、GitHub Release 用の成果物（インストーラ／Updater zip／latest.json）を `../release-v<版数>/` にステージします。公開手順は同フォルダの `RELEASE_UPLOAD.md` と `../DESIGN.md` の「v2.3.5」節を参照。

- **署名鍵の置き場所**: `desktop/.keys/`（`updater.key` が秘密鍵、`updater.key.password` がそのパスワード、`updater.key.pub` が公開鍵）。スクリプトが env 経由でビルドに渡します。**秘密鍵とパスワードはリポジトリや配布物に入れないこと**。失うと以後のアップデートを署名できなくなります。

前提: Rust（stable、rustup推奨）と Node.js。Tauri のビルド前に、フロントエンドを `cd ../game && npm ci && npm run build` で `dist/index.html` へビルドしておきます（`resync-rebuild.sh` と CI は自動で行います）。
アイコンは `icon-source.png`（ドット絵・自作）から `npx tauri icon icon-source.png` で `src-tauri/icons/` に生成済みです。

```sh
cd desktop
npm install   # @tauri-apps/cli を取得
```

### Windows（ネイティブ）

- Visual Studio Build Tools（C++ ワークロード）と WebView2 を用意
- `npx tauri build` → `src-tauri/target/release/bundle/nsis/` にインストーラ、`release/miyuke.exe` が単体exe

### macOS

- Xcode Command Line Tools を用意
- `npx tauri build` → `.app` / `.dmg` が生成されます（このプロジェクトでは未検証）

### Linux

```sh
sudo apt install libwebkit2gtk-4.1-dev libgtk-3-dev libayatana-appindicator3-dev \
  librsvg2-dev libsoup-3.0-dev build-essential libssl-dev libxdo-dev pkg-config
npx tauri build -b deb   # または appimage
```

### Linux から Windows へクロスビルド（今回の実績手順）

このVM（Linux）から Windows 版を実際にビルドした手順です:

```sh
rustup target add x86_64-pc-windows-msvc
# cargo-xwin を導入（MSVC CRT / Windows SDK を自動取得します。初回は数GB）
cargo install cargo-xwin   # または GitHub Releases のバイナリ
sudo apt install clang lld nsis   # lld-link / llvm-rc / makensis が必要
export XWIN_ACCEPT_LICENSE=1
# clang-cl という名前が無い環境では、clang のCL互換モードをラップする:
#   ~/.cargo/bin/clang-cl -> exec /usr/bin/clang --driver-mode=cl "$@"
npx tauri build --target x86_64-pc-windows-msvc --runner cargo-xwin -b nsis -- --xwin-arch x86_64
```

## 実測（このVM: 2 vCPU / 約8GB RAM、2026-10-24）

| 対象 | サイズ |
|---|---|
| Linux バイナリ | 7.5 MB（7,495,824 B） |
| Linux .deb | 3.0 MB（3,008,018 B） |
| Windows 単体exe | 8.5 MB（8,487,936 B、PE32+ GUI x86-64 を確認） |
| Windows NSISインストーラ | 2.1 MB（2,086,527 B） |
| 配布zip（myuke-desktop-windows.zip） | 約4.6 MB |

- Linux版を Xvfb（1280×960）上で実バイナリ検証:
  - 既定のストリップ起動でウィンドウが **1280×210・+0+750**（作業領域いっぱいの幅×210、底辺吸着）になり、ルートウィンドウ撮影で「壁紙の上に枠なしでペットとHUDだけが描かれる」ことを確認
  - HUDの「ひらく」ボタンを実際にクリック → フルモード **1180×860・+50+50** に切替わり、管理画面ヘッダーの「デスクトップに戻す」をクリック → ストリップ **1280×210・+0+750** に復帰（往復を実測）
  - `MIYUKE_START_MODE=full` のクリーン起動でも 1180×860・+50+50。フル形状が `miyuke-shell.json` に保存されること、ストリップ中に進んだゲーム進行がフル画面にそのまま引き継がれること（単一インスタンス）も確認
  - （当時）ブラウザ単体の `game/index.html#strip`（1280×210・壁紙グラデーション上）でも、机のみゅけ・散歩するスタッフ・吹き出し・HUDチップの描画を確認
  - ヒットゾーン式クリック透過を `MIYUKE_DEBUG_HIT=1` のログ＋xdotool で実測: 帯の何もない所（左端）にポインタを置くと `ignore=true`（素通し）、机の上に移すと `ignore=false` に切替わり、画面中央（ウィンドウ外）に逃がしても異常なく帯へ戻れば再び切替わる。ゾーン数が起動直後の吹き出しの消滅に連動して 4→3 に変わることもログで確認（再現スクリプト: `desktop/hit-test.sh` ほか）
  - OS全体の入力カウントを `MIYUKE_DEBUG_INPUT=1` のログ＋xdotool 合成入力で実測（再現スクリプト: `desktop/input-test.sh`）: 既定 OFF では合成入力を飛ばしてもリスナーは起動せず集計はゼロ。設定 ON では打鍵 40 回 → 集計 **keys=40**（完全一致）、矩形パス移動＋クリック位置へのジャンプ = 1940px → **distPx=1940**（計算一致）、クリック 3 回 → **clicks=3**（完全一致）
- 待機時リソース（Xvfb＋ソフトウェア描画での参考値・旧計測）: プロセスツリー合計 RSS 約350MB（WebKitGTK の3プロセス合算。共有ページの二重計上を含みます）、アイドルCPU は 1コアの約5%
- **Windows 版バイナリはこの環境では実行確認できていません**（Windows 実機がないため）。動作の証明は Linux 版ビルドで行い、Windows 版は同じソース・同じ手順のクロスビルド成果物です。特に OS 全体の入力カウント（rdev の Windows フックと UIPI の挙動）は Windows 実機での最終確認が必要です。実機で起動してトレイ・セーブ・入力カウントを確認するのが次のステップです
- トレイメニューのクリック操作そのものは Xvfb（トレイホスト無し）では未検証です。ただしモード切替はページ側ボタンと同一の `apply_mode` 経路で、そちらは実クリックで往復確認済みです
